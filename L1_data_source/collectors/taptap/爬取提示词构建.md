# TapTap 明日方舟评价爬取规格（可落地版）

> 基于实测接口 + `TAPTAP网页数据json` 样本核对。  
> 目标：`app_id=70253`，评价列表，结构化入库。

---

## 1. 接口定案

| 项 | 值 |
|----|-----|
| 方法 | GET |
| 路径 | `https://www.taptap.cn/webapiv2/review/v2/list-by-app` |
| app_id | `70253`（明日方舟；勿用 173799） |
| limit | **固定 10**（不改） |
| sort | `new`（从新到旧） |
| from | 偏移：`0, 10, 20, …` |
| stage_type | 样本请求里可为空或 `2`；以你浏览器实际能通的为准，写入配置 |
| X-UA | **必填**；从浏览器复制，放环境变量 `TAPTAP_X_UA`，不写死进仓库 |
| 翻页 | 也可跟响应里的 `data.next_page`（相对路径）拼到 `https://www.taptap.cn` |

样本响应额外字段：

- `data.total`：接口给的 total（样本为 10000，**不等于**全站评价总数，勿当全量口径）
- `data.next_page`：下一页相对 URL
- `data.list[]`：每项 `type=moment`，评论在 `moment.review`

合规：

- 只采公开评价；控制频率（建议页间 sleep 0.5～2s）
- 遇 403 / 429 / 验证码 / 登录墙：**停或降速**，不绕过
- 不把昵称、完整 user_id 公开到 GitHub

## 2. 采集模式

### 2.1 全量模式（总体分析）

- `from=0` 起按 `new` 向旧翻
- 停止条件（任一满足即停）：
  1. `list` 为空
  2. 本页条数 `< 10`
  3. 本页全部评论 `publish_time` **早于**指定起始日期
  4. 已采条数 ≥ 指定上限
  5. 连续 N 页无新增（相对本地库）
  6. （增量场景）已碰到上次水位线评论

### 2.2 增量模式（日报 / 周报）

- 同样 `sort=new` 从 `from=0` 开始
- 停在「评论发布时间 ≤ 上次成功水位」或「评论 ID 已在库且未变更」
- 若正文 / 评分 / `edited_time` / 点赞等变化 → **更新**，不丢弃

每次 run 写 run_log：

- 开始/结束时间、请求页数、获取数、新增数、更新数、重复数、失败数
- 最后成功 `from`、最新评论 ID、最新发布时间

断点：`checkpoint.json` 保存 `last_from` / `watermark_review_id` / `watermark_publish_time`，中断可续跑。

## 3. 字段映射（样本已验证）

路径前缀：`item.moment` → 下表写相对路径。

### 3.1 元数据（采集侧生成）

| 目标字段 | 来源 | 说明 |
|----------|------|------|
| review_id | `review.id` | **主键** |
| moment_id | `id_str` | 动态 ID |
| app_id | `app.id` 或固定 70253 | |
| source_url | 拼：`https://www.taptap.cn/review/{review_id}` | 若站内规则变化再改 |
| request_from | 本次请求的 from | |
| crawled_at | 本机抓取时间 ISO | |
| raw_json | 整条 `item` 原文 | 建议另存 raw/，表里可只存路径 |

### 3.2 用户

| 目标字段 | 来源 | 样本情况 |
|----------|------|----------|
| user_name | `author.user.name` | 有 |
| user_id | `author.user.id` | 有 |
| user_id_hash | 对 user_id 做 hash/截断 | **本地生成**，对外用这个 |
| avatar_url | `author.user.avatar` | 有 |
| is_moderator | `author.user.is_moderator` | 有 |
| user_level | — | **本列表接口无**；`review_comments[].author.badges[].level` 是回复者徽章，勿当评价作者等级 |
| verified | — | **本列表接口无明确认证字段** |

### 3.3 正文与标签

| 目标字段 | 来源 | 样本情况 |
|----------|------|----------|
| title | — | **无**（评价一般无标题） |
| text | `review.contents.text` | 有 |
| raw_text | `review.contents.raw_text` | 有 |
| pros / cons | — | **无独立优缺点字段** |
| rating_tags | `review.ratings[]` → `{type,value,label}` | 有，如「策略性 up/down」 |
| stage | `review.stage` | 有 |
| stage_label | `review.stage_label` | 如「玩过」 |
| source_code | `review.source` | 数值，含义待对照表 |
| language | — | **无**；可后置语言检测，第一版不做 |
| is_edited | `edited` 或 `edited_time != created_time` | 部分有 `edited: true` |
| edited_time | `edited_time` | Unix 秒 |
| publish_time | `publish_time` / `created_time` | Unix 秒；入库转北京时间 |

### 3.4 评分

| 目标字段 | 来源 | 说明 |
|----------|------|------|
| score_raw | `review.score` | 样本为 1～5 分制 |
| score_max | 固定 `5` | 个人评价满分；勿与 app 总评 10 分混用 |
| score_norm | `score_raw / 5` | 0～1，可选 |
| is_recommend | 规则：`score_raw >= 4` 可标推荐（自定口径，写进字典） | 接口无直接字段 |

### 3.5 游玩时长

| 目标字段 | 来源 | 说明 |
|----------|------|------|
| played_spent_sec | `review.played_spent` | 秒 |
| total_played_spent_sec | `review.total_played_spent` | 秒 |
| played_hours | 秒 / 3600 | 派生 |
| played_tips | — | **本接口无「1h+」文案字段**；可自己格式化 |
| hidden_spent | `review.hidden_spent` | bool，可能隐藏时长 |

### 3.6 图片 / 媒体

| 目标字段 | 来源 | 说明 |
|----------|------|------|
| image_urls | `review.images[].url` | 有则存在 |
| image_original_urls | `review.images[].original_url` | |
| image_count | len(images) | |
| video_urls | — | **样本未见**；有则记，无则空 |

第一版：**只存 URL，不下载图片**（避免体积与版权问题）。

### 3.7 设备 / 平台

| 目标字段 | 来源 | 说明 |
|----------|------|------|
| device_raw | `device` | 原文，如 `PC 客户端` / `OPPO A3 Pro 5G/...` |
| publish_platform | 由 `device_raw` 规则映射 | PC / Android / iOS / Web / 未知 |
| os / device_model / client_version | 从 `device_raw` 启发式解析 | 解析失败填未知 |
| game_runtime_platform | — | **列表接口难区分「游戏运行平台」与「发评设备」**；第一版只保留 `device_raw` + 映射后的 publish_platform |

### 3.8 互动

| 目标字段 | 来源 | 说明 |
|----------|------|------|
| support_count | `stat.supports` | 点赞/有用类 |
| reply_preview | `review.review_comments` | 可能带少量回复预览 |
| reply_count | — | **列表接口无明确总数**；可用 `len(review_comments)` 作「预览条数」，勿当全量回复数 |
| repost / favorite / official_reply | — | **列表里不全**；`review_comments[].is_official` 可标官方回复预览 |
| is_pinned / is_featured | — | **本样本未见** |

### 3.9 版本信息

| 目标字段 | 来源 | 说明 |
|----------|------|------|
| game_version | — | **评价列表无** |
| app 侧总评等 | `moment.app.stat.rating` | 这是**游戏页汇总**，每条评论重复；可另表存 app 快照，不要当「该评论对应版本」 |

## 4. 第一版必采（MVP）

只落这些，就能支撑后续结构化标注 + 日/周报：

1. `review_id`, `moment_id`, `app_id`, `request_from`, `crawled_at`
2. `user_id_hash`, `user_name`（本地可留，公开脱敏）
3. `text`, `score_raw`, `rating_tags`, `stage_label`
4. `played_spent_sec`, `played_hours`, `hidden_spent`
5. `device_raw`, `publish_platform`
6. `publish_time`, `edited_time`, `is_edited`
7. `support_count`, `image_count`, `image_urls`
8. `raw_json` 路径

其余字段：接口有则填，无则空；**不要为凑字段去绕过安全措施另打接口**。

---

## 5. 数据质量检查（跑完输出 MD 报告）

- review_id 是否重复  
- 空正文比例  
- score 是否在 1～5  
- publish_time 是否整体从新到旧  
- played_spent 是否为负  
- 相邻页 review_id 重叠率过高  
- `device_raw` 出现未映射新值  
- JSON 结构相对上次 schema 是否变更（关键字段缺失告警）  

---

## 6. 异常处理

| 情况 | 动作 |
|------|------|
| 超时 / 连接失败 | 重试 2～3 次，指数退避 |
| 403 / 429 | 停止本 run，写日志，更新 checkpoint |
| 5xx | 退避重试，超限则停 |
| 非 JSON | 存原始响应片段，跳过本页或停 |
| 单条缺字段 | 该条记 warning，不整页失败 |
| 中断 | 读 checkpoint 续跑 |


常用命令：

```bash
# 全量至 3000 条
python L1_data_source/collectors/taptap/crawl_taptap_reviews.py --mode full --max-records 3000

# 增量（日报/周报）
python L1_data_source/collectors/taptap/crawl_taptap_reviews.py --mode incremental --max-records 5000

# 断点续跑
python L1_data_source/collectors/taptap/crawl_taptap_reviews.py --mode full --resume --max-records 5000
```
