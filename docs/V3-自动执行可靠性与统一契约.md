# V3 Alpha16：自动执行可靠性与统一契约

本版对应三个阶段：可靠交付、统一 Agent Contract、统一工具执行与研究预算。产品仍是全自动系统：后台发现热点、补查证据、判断并归档情报与素材、有机会时生成增长创意；使用者打开五个入口读取成果，需要核查时查看依据。

“任务”是后台自动生成的工作项，不是要求使用者创建的事项。主、子 Agent 的分工也没有增加：一个业务主 Agent，一个所属研究子 Agent，多次模型调用共同完成工作。

## 1. 自动任务如何避免重复、过期和半份交付

实现：[`runtime_guard.py`](../agent_v3/runtime_guard.py)、[`work.py`](../agent_v3/work.py)、[`store.py`](../agent_v3/store.py)。

| 机制 | 实际行为 | 为什么需要 |
| --- | --- | --- |
| 运行租约 | `worker_lease` 限定当前后台运行；`worker_fence` 保存随机领取凭证。续租要求同一有效凭证，过期后不能原地复活 | 旧进程迟到的结果不能覆盖接管者 |
| 工作项租约 | `work_item` 保存阶段、话题版本、业务条件版本、领取 token、期限、次数和状态；领取在 `BEGIN IMMEDIATE` 中完成 | 两个数据库连接竞争时只有一个领取成功 |
| 幂等任务身份 | 阶段、话题版本、提示词及业务条件版本确定工作项身份；普通重复入队不会重做已完成工作 | 采集重复、普通榜单波动不应重复生产 |
| 交付依据快照 | 模型调用前保存话题 fingerprint、来源内容哈希、URL、日期与业务条件版本 | 模型返回时若依据已变，拒绝过期交付 |
| 原子交付 | 交付事务内检查租约和依据，保存成果，再写完成状态及 `delivery_receipt`，最后重新检查并统一提交 | 要么整份成果和回执都提交，要么都回滚 |
| 嵌套保存保护 | 老保存函数调用 `commit()` 或连接上下文时，不能提前提交外层交付；内层失败会让整份交付回滚 | 防止“素材已写入，但创意或完成回执没写入” |
| 自动恢复 | 新运行接管过期运行，标记原运行／周期中断；到期工作项恢复待办并重新领取 | 崩溃后无需使用者点击“重新运行” |
| 补查更新 | 自动补查有新结论时可更新业务判断，使用新的领取 token；完成回执按工作项与 token 保留 | 正常更新情报与同一次交付重放分开处理 |

当前运行层使用 SQLite 的短写事务和单个后台工作线程，适合本地部署。工作项租约为8分钟，托管业务周期的运行租约为20分钟；模型调用前、工具调用前续租。过期运行要等租约到期并由调度检查后接管，并不承诺进程崩溃后立刻恢复。

模型、联网与浏览器请求在交付事务之外执行，避免网络等待长期锁住数据库。写来源证据也受运行凭证保护；失效执行者仍可记录拒绝日志和工具异常台账，但不能保存新证据或业务成果。释放旧租约只匹配旧 owner 和 token，不能释放新执行者的租约。

**保证范围是数据库写入和交付身份。** 进程在请求模型或网站后、收到结果前崩溃，远端可能已处理请求并产生用量；本系统无法保证远端请求恰好一次，也不能推断那次请求免费。已提交的完整交付不会因重启重复执行；未提交的调用可能在后续恢复时重新请求。

迁移只新增表以及工作项的 `lease_token`、`context_version` 字段，保留原有来源、成果与历史。重复打开数据库可重复执行初始化。升级前保留源码及 SQLite 快照；没有删除项目文件。

## 2. 主、子 Agent 如何共享一套 Contract

实现：[`contracts.py`](../agent_v3/contracts.py)、[`task_packets.py`](../agent_v3/task_packets.py)、[`model.py`](../agent_v3/model.py)。契约版本为 `agent-contract-v3.16`。

Contract 是程序与 AI 之间的交付约定：输入什么、属于哪个执行角色、输出哪些字段、如何引用来源、哪些失败不能入库。它不是新增一个 Agent，也不要求使用者填表。

| 角色 | 已注册阶段 |
| --- | --- |
| 业务主 Agent | `main_plan`、`intelligence`、`creative_plan`、`creative_production`、兼容 `creative` |
| 研究子 Agent | `research_plan`、`interpretation`、`event_relation` |
| 接入检查 | `readiness` |

统一执行入口是 `contracts.run_task()`：

1. 验证阶段已注册、输入是对象、输出 Schema 合法，计算输入指纹。
2. 给供应商适配器传入独立输入和 Schema 副本。
3. 只接受最终结果；返回元数据保留模型、传输方式、用量、结束原因、推理强度等白名单字段。
4. 拒绝超出任务时间预算的交付，以及截断、工具调用中断、内容过滤等未完成响应。
5. 本地验证 JSON Schema，再检查 `fact_refs`／`basis_refs` 是否属于本次证据包。Python 布尔值也不能冒充整数引用。
6. 上层业务继续执行逐字引用、来源身份、时间、风险、TapTap 业务条件及交付质量检查；通过后才进入原子保存。

统一返回结构的核心字段如下，`result` 的具体格式由阶段决定：

```text
result             最终业务 JSON
contract_version   公共契约版本
stage / agent_role 阶段与角色
input_fingerprint  本次输入包指纹
model / transport  实际模型与调用方式
usage / seconds    适配器报告的用量与耗时
finish_reason      供应商提供时记录结束原因
```

DeepSeek 和太空兔从最终 `content` 解析 JSON，OpenCode 从它的结构化交付读取 JSON。没有原生任务接口的现有 Chat Completions 客户端经过 `chat_task()` 适配，仍接受相同校验。业务代码统一走 Contract，供应商差异留在适配器中。

`reasoning_content`、私有续接上下文和推理文本不进入业务结果或公共任务元数据；允许记录“是否有推理”及 token 计量。最终结果为空时不能拿推理过程填补。时间预算检查会拒绝迟到输出；实际请求终止与网络超时仍由具体适配器负责，不把事后检查描述成强制取消远端请求。

共享 Contract 不替代语义判断：符合格式且引用存在，不意味着模型正确理解了热点，也不意味着创意能增长。本版保证换供应商后继续使用相同约束，不宣称各供应商质量相同。

## 3. 工具、研究预算和异常如何追踪

实现：[`tool_executor.py`](../agent_v3/tool_executor.py)、[`research.py`](../agent_v3/research.py)、[`tools.py`](../agent_v3/tools.py)。

研究工具统一通过 Tool Executor 调度：正文补读、新闻／网页搜索、浏览器正文、截图 OCR、评论区截图读取和评论采样。兼容 GrowthTools 的注册工具也经过相同台账；模型不能传入任意 shell 或未注册工具名。

```text
注册工具与参数
  → 检查运行租约及剩余预算
  → SQLite 事务预留预算、写入调用记录
  → 释放事务，执行真实工具
  → 核对返回用量、来源与运行凭证
  → 保存结果摘要和异常，结算预算
```

| 台账 | 保存内容 |
| --- | --- |
| `tool_budget` | 每个运行／预算域的总预算、已消费量、预留量 |
| `tool_execution` | 调用编号、工具、参数、起止时间、状态、预留／结算量、耗时、结果摘要、来源、异常、金额报告状态 |

剩余预算为 `budget - spent - reserved`。同一运行的新执行器不能通过传入更大的 limit 扩大已建预算；并发执行器在联网前共同预留预算。命中缓存且报告0次实际调用时归还预留。本地读取工具可以使用0次网络预算，仍记录调用和来源。

抛出异常或返回异常格式时，实际用量可能不明，保守按预留上限占用，记录异常类型，不记录异常中的原始私密响应。工具明确返回失败时也会标为失败。进程崩溃后，未完成调用标为 `interrupted`、金额状态标为 `unknown_after_interruption`，原预算预留保留；不能因为不知道用量就反复释放额度。

来源记录包含实际证据编号、URL、标题及发布日期。本地运行详情 `Store.get_run()` 提供 `tool_calls` 和 `tool_budgets`。工具台账不直接进入公开成果 JSON，也没有为普通使用者添加启动任务按钮。

**工具次数、token 与金额分别记录。** 当前来源工具不返回实际计费金额，`monetary_cost` 为空，`cost_status` 标明未报告或中断未知；不将网络次数当作费用。模型的 token 和供应商报告金额仍由模型调用记录保留。预算主要限制每轮研究工具消耗，不是整个平台的月度账单上限。

## 4. 验收与当前边界

新增回归模块 [`test_runtime16.py`](../agent_v3/tests/test_runtime16.py)，并加入 CI，包含真实文件 SQLite、多连接竞争和真实子进程 `os._exit()` 故障注入。

| 阶段 | 验收覆盖 |
| --- | --- |
| 租约与交付 | 并发只能领取一次；过期执行者不能续租、写证据或结束新工作项；来源正文／URL／日期、话题、业务条件变化拒写；期限在保存过程中失效也回滚；嵌套保存失败全量回滚；提交前崩溃恢复，提交后崩溃不重复；补查更新保留两次回执且旧重放无害 |
| Agent Contract | 使用实际 DeepSeek、Space Bunny、OpenCode 适配器，同一主 Agent／子 Agent Schema 和固定输出经过离线传输验证；缺字段、虚构引用被全部拒绝；Chat 适配器仅使用最终 content，推理与续接数据不进入返回结果 |
| Tool Executor | 网络前预留；重建执行器不扩预算；真实两个连接竞争共用预算；缓存释放；失败与异常格式可追踪；本地工具0网络消耗；未知工具拒绝；失效工具不能写证据；真实工具进程崩溃留下中断和未知成本记录 |

本轮使用隔离数据库和模拟供应商 HTTP／OpenCode 传输，不请求付费模型，不向真实成果库写测试数据。供应商额度暂停继续保留。离线契约验收不能代替额度恢复后的真实长期自动运行、热点理解和创意品质验收；聚类质量、信息覆盖与实际增长价值仍需持续打磨。
