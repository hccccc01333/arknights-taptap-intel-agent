# V3 Alpha13：自动交付与补查闭环

## 本轮目标

使用者登录后只浏览热点发现、事件跟踪、情报档案、素材库、增长创意。采集、初筛、研究和业务制作由后台推进，页面打开不触发生产任务。情报、素材和创意是主 Agent 的三个独立判断；研究子 Agent 提供证据和事件解读。执行效果反馈本轮不建设，已有反馈接口与历史记录保留，正常界面不展示反馈表单。

## 用户界面

- 正常入口只保留五页；不展示“采集并发现”“处理现有线索”、运行覆盖或配置入口。
- 情报按新作与版本、玩家需求、社区创作、市场动向、风险观察归类。
- 素材按文案、脚本、游戏改编、表达模板等用途归类；有摘要，点击后展开使用稿和依据。
- 创意按发现游戏、社区参与、回访活跃、预约体验归类；点击后看人群、机制、路径、文案、脚本及执行条件。
- 原文、截图、评论、版本和自动补查状态在事件详情可核查；原采集标题不作为默认候选列表让用户自行研究。
- 页面每15秒读取后台结果；连接失败显示自动重连状态，不继续宣称正在更新。
- 已有旧成果用保守的目录规则补分类，标记 `legacy_library_rule`，不改写原始事实，也不冒充新的 AI 判断。新任务由模型输出类别与平台字段。

保留旧运营工作台源码 `V3OperatorApp` 用于版本比较，不作为正常导航。内部调试接口保留。此项是代码保留，不代表页面中另设了一个使用者必须操作的后台。

## 后台自动化

原先每15分钟在同一周期初筛18条、深入处理两个话题，积压推进太慢。现将初筛独立为主 Agent 的低成本任务：每次最多两批、每批40条；不委派研究或制作创意。后台每30秒检查调度，初筛任务间隔1分钟、深度任务间隔3分钟、采集默认60分钟。间隔表示可以再次开始的时点，单个工作租约保证任务不会并行叠加；长任务期间后续任务等待，因此不承诺固定每分钟处理80条。

优先处理到期采集及深度任务，再用间隙推进初筛，避免初筛占满后台。模型退避时保存任务，来源采集继续按自己的周期运行。AI专用周期不反复导入全部V1/V2文件。新提示词/业务契约需要重新判断时，已完成旧版本的记录不能阻止新契约进入自动队列。

自动运行由项目后端启动，和浏览器是否打开无关；本地机器及后端仍需要运行。此次没有另行部署常驻服务或云端服务。

## 子 Agent 补查

研究返回的可核查缺口写成 `next_actions`：具体问题、检索词和工具，持久化至 `research_followup`。兼容旧解读的明确评论、正文、时间及身份缺口；总体情绪比例、未来效果、预算和授权不是普通联网搜索能解决的事项，保留局限而不假装可查。

每个话题当前版本最多两项未解决问题，防止换一种措辞就扩出无限任务。每轮最多安排一个补查任务，占用原有最多两个研究位置和六次来源调用预算，仍然是同一个研究子 Agent。评论先接口，失败可定位、滚动、截图和OCR；没有可识别评论就保留失败，不能将截图成功当成采样成功。

状态为已安排、正在补查、等待重试、已查证或等待新证据。模型声明“已查证”必须提供当前可引用证据；背景资料须先核对同一事件，评论问题必须有有效实际评论依据，不能用标题和正文代替。有效结论、原句、尝试历史和更新时间写回原事件。补查可以更新解读与主 Agent 判断，原业务版本保留；已有创意不会仅因重复补查而反复生成。

失败逐步退避；最多三次后等待新证据。真实来源内容版本变更后可重新安排；仅采集时间变化不会重置。任务进程崩溃留下的运行状态可在租约超时后恢复。这个闭环保证继续尝试与可核查状态，不保证公开网页一定能回答所有问题。

## 无关线索与空间

主 Agent明确判定 `unrelated + archive` 的当前候选退场，保留小型拒绝索引，同一内容和业务条件重新采集不会再次占用研究队列；新内容版本可重新筛选。不将语境不足、待观察或已产生业务成果的内容当垃圾。

只对完全无关且没有成果/研究引用的来源，清理一天前的重复渠道观测，每个渠道保留最新观测；SQLite空闲页可复用。原文、拒绝理由、引用证据、截图和历史成果保留。此次没有删除文件，没有无差别删除原文或回收整个数据库文件。用户的文件删除规则仍需逐文件说明和批准。
