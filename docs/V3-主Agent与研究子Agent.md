# V3 Alpha 9：业务主 Agent 与研究子 Agent

版本：`3.0.0-alpha.9`，2026-10-08。这是已实现的执行架构与阶段验收记录，不代表全网覆盖、分析准确率或实际增长效果已验收完成。

## 两个角色与程序边界

业务主 Agent 根据候选与业务条件，判断游戏直接相关、通用表达、可转化探索、不相关或信息不足；选择委派研究、直接分析、观察或归档，并向子 Agent 提出具体问题和检索词。游戏情报、可用素材与机会判断由同一个主 Agent 生成；有效机会才进入其创意规划和文案/脚本制作阶段。模型调用分段不增加 Agent 身份。

研究子 Agent 使用主 Agent 的委派任务选择有限的工具动作，补充公开搜索、详情或评论，再返回有来源的热点解读、实际读取范围与未解决的问题。正文和评论不足时保留缺口，不能伪造讨论或争议。子 Agent 不生成 TapTap 增长方案，主 Agent 可以根据研究结果维持观察而不制作创意。

程序执行来源采集、调度、版本与缓存、预算、校验、入库和恢复。每周期最多选择两个业务话题、保留一个探索名额、六次来源工具预算、一个创意任务；没有委派时不使用剩余预算去补读其他候选。未选择的候选不进入主 Agent 本轮处理。供模型筛选的批次最多十八条，游戏来源有保留位置，但游戏渠道不能直接证明内容属于游戏。

## 数据与展示

新增 `main_decision`、`topic_interpretation`、`game_signal` 与 `material_context`，旧来源、任务和分析记录保留。

- 热点：可读标题、一句话概括、背景/核心、时间线、真实观点或报道转述、有依据的争议、缺口和逐段引用。默认列表只显示当前来源版本、解读充分且有实际榜单依据的记录。普通发现页位置、新闻发布和搜索命中不作为热搜热度。旧内容的日期前置，原模型标题和摘要保留用于核查。
- 情报：涉及的游戏/玩家场景、观察到的变化、意义、影响假设、下一观察条件及原文依据。只有系统重新采集旧内容且无新变化的结果保留背景分析，不计游戏情报。游戏线索不等于官方确认或已验证需求。
- 素材：逐字摘录、表达模式或原创游戏改编，须说明具体玩家场景和使用实例。原始链接和未转化泛领域模式归来源资料，不计可用素材；制作草案与成品分开。情报、素材允许分别为空。
- 创意：沿用可续作的方案规划与文案/脚本制作，由同一业务主 Agent 执行，读取已保存成果与真实业务条件。

热点页面默认展示解读，原文、引用与工具过程位于核查入口；情报页默认展示游戏情报，历史泛领域分析可展开。素材库默认展示可用素材和草案，来源资料单独切换。业务条件变更重做业务分析，事件解读可复用；已有观察结论不会一直占据前两个处理名额。

## 联网能力与模型处理

新增公开网页搜索适配器：Bing RSS 返回真实搜索命中，已接入域名的网页按预算提取正文。与原有单一媒体新闻检索、详情和平台评论读取并存。搜索摘要、实际正文、历史评论分别标明；搜索日期不冒充新闻发布日期，搜索命中不证明同一事件。仅已接入公开域名可补读正文，登录、验证码、动态页面及未接入网站仍有读取限制。

继续使用配置中的 DeepSeek Flash、low 与单次总上限 16,384 token；研究规划阶段从 2,048 调整为 4,096，以避免推理与最终 JSON 共用预算时截断。最终业务结果仅解析 `message.content`，不保存 `reasoning_content`。模型步骤记录角色、阶段、结束原因和用量；失败的结构化辅助调用也保存已收到用量，价格与未返回费用不虚构。
