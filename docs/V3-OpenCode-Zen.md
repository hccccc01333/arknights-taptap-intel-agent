# V3 OpenCode Zen 接入

版本：3.0.0-alpha.4，2026-10-07。

Zen 免费模型通过官方 OpenCode 原生 Agent 执行完整情报或创意任务。V3 负责采集、安排任务、准备真实来源包、校验交付、积累素材和版本记录。此接入不把 Zen 当作另一个 Agent 框架的免费模型接口。

## 运行

```powershell
python -X utf8 scripts/install_opencode.py
python -X utf8 -m agent_v3.opencode_zen models
python -X utf8 -m agent_v3.opencode_zen probe --model opencode/big-pickle
```

安装脚本固定官方 npm 包 `opencode-windows-x64@1.18.35`，核对 npm SHA-512 完整性并记录可执行文件 SHA-256，安装到项目忽略目录 `.toolchain/opencode/1.18.35/`。不覆盖已有安装。其他平台安装官方 CLI 后设置 `V3_OPENCODE_BIN`。恢复源码快照后需重新安装该依赖。

在 V3「业务与自动运行」选择 OpenCode Zen 模型并保存。当前业务模型选择 Big Pickle。Ling 历史上通过过真实独立情报任务；Big Pickle 历史上通过读取和结构化连接验证。最近两者业务任务、普通消息及小型连接复验均超时，用户确认免费额度耗尽，已暂停后续 Zen AI 请求。截图中的 Ling、Fledge、LongCat、MiMo、Muse 等免费模型也可选择；列出和安装不表示每个模型已经通过真实业务验收。

## 推理强度

Ling 模型可在「业务与自动运行」选择并保存低、中、高或模型默认。设置保存在 V3 SQLite 中，新任务创建官方 OpenCode 运行时后，通过 `provider.opencode.models.<model>.options.reasoningEffort` 传递；默认使用低档，选择模型默认时不传此参数。切换强度不改变最大输出长度、任务总时限或免费模型约束。任务执行期间不能改配置，观察账号不能写入。

当前单次上游请求预算 150 秒，客户端输出预算 6500 token，包含模型消耗的推理部分；情报/创意仍受下述总时限约束。之前 Ling 曾消耗 6490 推理 token 并因长度结束，没有结构化结果。设置 low 后实际任务能生成完整分析，但素材字段契约误用证据编号规则，导致最初结果被拒绝；该契约现已修正，并按本次真实来源限制编号及逐字引文候选。不能把契约错误归为免费模型不可用。

档位是向供应商发送的请求选项，不是精确推理 token 上限。真实已保存的情报使用 low、耗时 78.34 秒、810 输出 token 和 4992 推理 token；中、高档尚未做业务质量对照。其余 Zen 模型保留原生默认配置，不能假设使用相同推理参数。

## 任务边界

官方 `opencode serve --pure` 由 V3 后端按需启动，绑定随机本地端口，使用进程内随机密码。配置、缓存、会话和公开任务输入独立存放在 `.toolchain/opencode/runtime/`，不修改用户的桌面端配置或使用其他提供商的凭证。

原生 `build` Agent 读取任务的 `input.json`，完成情报提炼或增长创意包，通过 OpenCode `StructuredOutput` 提交完整业务 JSON。V3 不在 OpenCode 外代替它进行逐轮模型决策。来源只能读自动准备的公开任务目录，自动文件修改被禁用，其余权限申请由工作器拒绝；不允许删除、终端执行或调用其他 Agent。Windows 权限使用工作树相对路径，并同时处理两种分隔符。

Alpha 4 每条情报最多两次原生交付尝试；增长创意分为独立的创意规划与文案/脚本制作，每阶段最多两次交付尝试，第二次用于修正业务校验错误。所有阶段仍在同一总预算内；沿用情报 180 秒、创意 360 秒总预算。每个 OpenCode 任务最多 10 次原生迭代。请求、响应大小和总时长有额外限制；超时终止会话，来源和待处理任务保留。

Alpha 4 的引用用整数 ref 选择原文和素材，V3 映射回真实编号、指纹和逐字来源。原生情报使用现有的摘要、事实引文、情绪、需求、传播方式、内容形式、可复用表达和机会判断契约。观察或归档结果可以独立保存。只有明确的机会进入原生创意任务，交付具体人群、吸引点、站外传播、TapTap 承接、用户动作、文案及脚本或视觉制作方案。JSON 结构、已提供来源、逐字引用、话题版本和素材复用仍须通过 V3 校验。

Alpha 4 在模型调用前按已有详情连接器补读新闻正文或视频简介，每周期最多两次；成功与失败各有重试时间，补读后的内容版本重新入队。普通社会/生活热搜尚无正文连接器，评论与视频转录仍未读取。原生 Agent 本身使用准备好的来源包，不直接发起外部搜索。仅有标题或摘要时须说明范围；不能将结构通过或模型接通算作分析、发现和创意质量达标。

## 免费与故障

仅启用 `opencode` 提供商，限定截图中的七个免费模型。调用前读取官方 OpenCode 目录中的输入、输出、缓存和扩展价格，价格缺失或非零时停止；同时要求工具调用能力。未选择模型时的原生默认模型与内部小模型均使用 Big Pickle；业务任务使用明确保存的选择，不自动切换付费模型。每次交付核对实际模型及消息、会话报告的零费用。

403、429、402 和其他失败分别保留原因和退避时间。Zen 的退避与 OpenRouter 独立，Zen 免费层拒绝或限流会暂停整组 Zen 任务，避免逐个模型重复请求。单个模型的超时不阻断其他 Zen 模型。切换到可用服务后可恢复此前因供应商失败延期的工作。

已确认免费额度耗尽时，在「业务与自动运行 → Zen 免费额度」保存暂停状态。暂停持久化在 V3 SQLite，应用于所有 Zen 模型；不猜测每日恢复时刻，重启、切换 Zen 模型不会解除。采集、正文补读与素材入库继续，AI 工作保留。确认额度恢复后点击「额度恢复后继续 AI 任务」，沿用已有队列及制作规划；已观察的供应商限流退避仍生效。该按钮不发起即时付费调用。连接探测命令也会消耗真实模型请求，暂停期间不要反复探测。

初始直连 Zen API 与只输出工具决策的精简 Agent 调用均返回 403。改为真正的 OpenCode 原生完整任务后，Big Pickle 已完成真实输入文件读取和结构化交付，报告费用为 0。Ling 也曾遇到上游 429 和超时；调整配置并修正输入契约后，真实热点「张本智和吐槽对手：想赢高手只能乱打」已保存一条独立情报、两项表达素材。机会判断为 archive，不为体育热点强行生成增长创意。该结果标为未审核 AI 推断，不能代替内容质量验收。生活方式热点复验仍出现不完整交付和超时，本轮自动增长创意为 0，失败任务保留等待重试。

OpenCode 1.18.35 的格式化消息列表存在编码问题，因此使用官方同步消息接口获取最终 assistant 交付；任务期间另行拒绝未授权权限申请。运行记录保存会话 ID、来源包路径、用量和耗时，会话留在项目本地用于复查。结构化字段缺失等交付问题单独进入业务修正重试，不触发供应商故障退避；供应商拒绝、限流和连接超时仍按故障退避。
