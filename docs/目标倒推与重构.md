# 目标倒推与重构

> 建档：2026-10-01。起因：用户质疑 ——
> 「我们最初的目的是**服务游戏社区，完成全网热点追踪 —— 构建 AI 自动化情报与素材系统，
> 通过热点识别产出与 TapTap 相关的实际增长创意**。**AI 目前的参与为 0**，
> 我不是说 LLM 没钱的问题，而是 **LLM、agent、langgraph、harness 根本不是重点**。
> **如果你不需要这些也可以做成功，那么这些的意义是什么？推导重构。**」

---

## 0. 先把结论放在最前

1. **「AI 参与为 0」是事实**，我核实了（§1）。
2. **我错在两条**：① 顺序做反（先造护栏、车没上）② **产出端从未被验收**（§2）。
3. **实测穿帮**：现在最热话题的全部原料是「5 条新闻搬运 + 3 条 0 赞吐槽」——
   **连"成功"的门都摸不到**（§3）。
4. **倒推的结论**：AI 在链条的**末端两环（判断 + 生成）**；harness/LangGraph 是**那两环的护栏**。
   现在装它们 = **没装引擎先装护栏**（§4）。
5. ★ 但它们**不是没意义**：模型一旦进来，"不可复现 / 数字污染 / 不确定性成本"三类问题立刻出现，
   且只有这套东西能管住（§5）。**同时必须承认：若最终证明不需要模型也能产出可用创意，这套东西该删**
   —— 这是**待检验的假设**，不是我先假定它成立。
6. **重构四条**（§6）：产出立为唯一里程碑 · 补原料 · 装引擎 · AI 参与度作为唯一进度指标。

---

## 1. 事实核实：AI 参与 = 0（成立）

全 16 个模块里，**只有 3 个**真会调模型，而这 3 个在当前环境全部**降级兜底**：

| 环节 | 本该 AI 做什么 | 现状 | 实际 AI 参与 |
|---|---|---|---|
| 可发酵度判断（`ferment_judge`） | 判「这热点值不值得做」（语义） | 规则**代理分**兜底，且自标「**不可作为结论使用**」 | **0** |
| 官方排期解析（`announcements`） | 从公告抽结构化排期 | `raw_text` 兜底，排期视图出不来 | **0** |
| 简报执笔（`daily_agent`） | 写定性判断 | 模板兜底 | **0** |
| 素材：梗 / 二创角度 | 识别梗、生成创意角度 | 未实现，标注「需 LLM」 | **0** |

**所以：AI 的参与确实是 0。** 我做的 475 个测试、契约、图、harness —— **全是确定性代码**。
`ferment_judge` 那个"读语义 5/10 vs 字面匹配 0/10"的对照，**恰恰是在证明"AI 该上场"**，
而它现在**没上场**。

---

## 2. 我错在哪（不辩解，两条）

### 错一：顺序做反了

我造了护栏（harness / 契约 / LangGraph 图 / 幂等 / 预算 / 轨迹），**但车没上**。
更糟的是我把**最难、最值钱、最需要 AI 的那一环（判断 + 生成）反复排到最后**，
而把精力放在确定性、好测、好交付的控制面上 —— 这是**工程舒适区**。

### 错二（更要紧）：**产出端从未被验收**

我从没问过一个问题：

> **「我这条管道里流出来的东西，能不能支撑一次创意？」**

一次都没问。我一直在优化"数据的管道"，却**没有检验过管道出口**。
一旦检验，就穿帮了（§3）。**这才是"AI 参与 0"背后真正的病**——
不是"还没接模型"，而是**整套系统的验收标准里根本没有"产出"这一项**。

## 3. ★ 实测穿帮（今天最强的一条证据）

拿**素材最全的头号热点**「三角洲行动二周年」看它的全部原料：

**原帖引用 5 条（按 ups 降序取的前 5）**：
```
ups6  9月25号《三角洲行动》二洲年庆典的烽火明星表演赛在重庆华熙生物·润百颜ECM中心开打…
ups5  《三角洲行动》二周年官宣《影之刃零》联动，国产单机IP跨界合作引爆讨论…
ups5  一个硬核战术射击和一个暗黑武侠动作，这俩游戏居然官宣联动了！…
ups1  《三角洲行动》二周年庆典上线，总榜畅销冲至第4…
ups1  三角洲行动在二周年庆典上放了个大招，与国产武侠动作游戏影之刃零的联动…
```
→ **全是"新闻搬运"体，点赞 1–6**。这不是社区热帖，是媒体通稿的转载。

**热评金句 3 条**：
```
赞0  花钱买抑郁症监护室也是没谁[表情_嫌弃]
赞0  好不起来破模式 手游玩个锤子[表情_嫌弃]
赞0  从美臀发展到性感小肚皮[表情_嫌弃]
```
→ **赞全为 0，且看不出与"二周年"的关系**。

**为什么会这样（两个判据在真实数据上失效）**：
1. **原帖判据**："按 `ups` 降序" —— 但该话题下**根本没有高赞社区帖**，取出来的就是几条低赞新闻。
2. **金句判据**："**帖子内** `supports` 降序" —— 帖内评论**全是 0 赞**时，排序**退化为取前 N 条**
   （我实测那批评论的 supports 最大只有 10，多数为 0）→ **等于随机抽 3 条**。

**结构性缺口（跨 9 个话题统计）**：

| 事实 | 数值 |
|---|---|
| 评论素材能挂上话题的比例 | **21%**（110 条评论，只有 23 条的帖带 `hashtag_id`） |
| 9 个热点话题中「用户语声 = 0 条」的 | **6 个** |
| 根因 | 帖的**话题归属只在深采（`hashtag-feed`）这一条采集路径上有**；其余路径的帖没有 `hashtag_id` |

**结论**：`page_view 8032`（采样 91 次）这类 facts 是**平台话题页曝光**，
**不等于社区在讨论**。**我手里没有"社区在说什么"**，而**创意唯一的原料就是它**。

> **所以「不需要 AI 也能成功」这个前提，在今天的原料上根本不成立 —— 不是成功，是还没开赛。**

## 4. 严格倒推：从目标往回推每一环

**目标**：产出与 TapTap 相关的**实际增长创意**（"实际"= 能用、能被运营拿去执行）。

```
目标：产出「实际增长创意」
  ← 需要：**从社区语声里看出可用的角度**（玩家在气什么 / 玩什么梗 / 期待什么）
        ← 只有 AI 能做（语义理解，`ferment_judge` 已证：字面匹配 0/10 vs 读语义 5/10）
  ← 需要：**判断这个热点值不值得做、做哪个角度能带来增长**
        ← 只有 AI 能做（多步推理 + 常识）
  ← 需要：**话题下的用户语声**（评论 / 高赞 / 语境）
        ← 现状 21% 能挂话题、6/9 话题为 0  ← ★ 缺口在这
  ← 需要：热点时机（状态 / 变化率 / 首见时间）         ← ✅ 已有（topic_tracker）
  ← 需要：采集（帖 + 评论）                          ← ✅ 已有
  ← 需要：**可核验**（每条创意能追到素材 id + facts）   ← 需要 harness 的溯源/契约
  ← 需要：**可复现 / 不编数字 / 控成本**              ← 需要 harness 的轨迹/锁数/预算/降级
```

**倒推揭示的两件事**：

1. **AI 落在链条末端的"判断 + 生成"两环** —— 而这两环**恰好是我唯一没做的**。
2. **护栏（harness / 图 / 契约）在末端之后才有用** —— 它们是**末端两环的配套**，
   而现在末端不存在，所以它们**像没有引擎的护栏**。

**⇒ 所以准确的说法不是"harness/LangGraph 不是重点"，而是：它们是重点的配套，而重点是那两环 AI。**
（"不是重点"这个判断对**顺序**成立，对**必要性**不成立 —— 见 §5。）

## 5. 那么它们的意义是什么（正面回答 + 自我反驳）

### 5.1 意义：模型一旦进来，三类问题立刻出现，只有这套东西能管住

| 问题 | 为什么必然出现 | 谁来管 |
|---|---|---|
| **不可复现** | 同话题同模型，两次给出的创意不一样 → 出了好创意也复现不出、无法归因 | harness **轨迹** + 图 **checkpointer** |
| **数字污染** | 模型会编「热度 77.5%」这种看似精确的数字 | **facts 锁数** + State 守卫 + 契约 `text_access`（2026-10-01 刚立） |
| **不确定性成本** | 超时 / 402 / 幻觉 / 重复花钱 / 半途崩 | **预算** + **幂等** + **失败分派** + **分层降级** |

**这三条都不是"为了用框架而用框架"，是模型引入的固有属性。** 所以：
- 如果**要做**那两环 AI → 这套东西**必须有**（今天已经建好，等于把地基先打了）。
- 我错的只是**顺序**（先地基后引擎），不是**建它这件事本身**。

### 5.2 自我反驳（必须写下来）

> **如果最终证明"不需要模型也能产出可用创意"，那么 harness / LangGraph / 契约都应该删。**

比如：如果发现"把高赞评论按规则拼成运营清单"就已经够用（无需语义判断），
那这套控制面就是**过度工程**，该砍。**这是一个必须被检验的假设，我不先假定它成立。**

**怎么检验（0 成本办法）**：**人当模型，手工跑一次最后一环。**
- 做法：取出一个话题的 facts + 素材，人工写出 1 条创意，并记录"我需要看到什么才能写出来"。
- 结果会直接告出两件事：① 这套系统**缺哪些原料** ② 那些原料**是不是只有模型能处理**。
- **今天的实测已经给出前半段答案**：§3 表明 **现在连"人"都写不出创意来**（原料是 5 条新闻 + 3 条 0 赞吐槽）
  → **所以这个假设现在检验不了 —— 得先补原料。**

## 6. 重构（四条改动，按优先级）

### 改动 1｜把「产出 1 条可核验创意」立为**唯一里程碑**

其余全部降级为"服务该里程碑"。**可核验**的定义（硬要求，写进契约）：

- 每条创意必须带：**话题 id** + **支撑素材 id（可追到 origin）** + **引用的 facts 数字（可在 facts JSON 找回）**
- 说不出来源的创意 = **不算产出**

> 这一条的作用：让"产出端"第一次进入验收标准。**此前的验收标准里根本没有它。**

### 改动 2｜补原料（**不需要模型，立刻可做**）

1. **话题归属打通**：帖只有深采路径带 `hashtag_id` → 要求"任何进入素材库的帖必须可归属或显式标为
   *泛平台素材*"，并从**话题级创意**里排除后者。这是"改动 3"的前提。
2. **把「每话题可用语声数」变成监控指标**（今天是 6/9 话题为 0）→ 提深采 `comment-limit`、
   按需多轮累积、把 0 语声的话题**标记为"不可产创意"而不是硬产**。
3. **修失效的判据**：评论的"帖内 `supports` 降序"在全是 0 赞的帖上退化为随机
   → 改为"高赞优先；0 赞**不入候选**（标 `low_signal`）"，避免拿无关吐槽当素材。

### 改动 3｜装引擎（需要 key，但**可以先用"人当模型"占位跑通链路**）

1. 先写 `T6 创意生成` 的**契约 + prompt 规格**：
   输入 = 话题 facts + 素材 id 列表 + 语声统计；输出 = 创意 + 依据 + 溯源 id。
2. **人工填充一次**（human-as-model），把"模型该看到什么"变成具体规格 —— 顺带检验"是否需要模型"。
3. 模型接进来后，§5 的三类护栏**立刻兑现**。

### 改动 4｜**AI 参与度作为唯一进度指标**

今天 = **0%**。目标 = **每条创意都经过模型判断/生成**。
**不再用"测试数量/任务数量"当进度** —— 那些增长不等于目标接近。

---

## 7. 建议的第一步

**先做「改动 2 的第 1 条」（话题归属打通）+ 「改动 3 的第 1、2 条」（创意契约 + 人工占位）**：

- 改动 2 第 1 条**不需要模型**，且是改动 3 的前提；
- 改动 3 的第 1、2 条也**不需要模型**，但会把"最后一环要什么"变成**可核验的规格**——
  做完它，我们才知道"到底要不要模型"，而不是继续在控制面上加法。

**顺序上唯一的纪律：此后任何新增，都必须先回答"它服务"产出 1 条创意"的哪一步"。**
