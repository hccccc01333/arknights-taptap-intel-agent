## 1. Schema：v1.x → v1.4 解决了什么

早期单字段 `sentiment∈{正,中,负}` 会在三类样本上翻车：

| 痛点 | 现象 | v1.4 怎么拆 |
|------|------|-------------|
| 夸中带槽 | 「好玩就是有点肝」被打成负，或高级黑被当真心好评 | `literal` vs `intended` 分通道；整体态度跟 **intended** |
| 星级冲突 | 五星正文在骂 / 四星单点吐槽 | 星级只作弱线索；辱骂→负，单点机制槽可仍正/中 |
| 讽刺裂隙 | 褒义外壳 + 负面事实、排比模板好评 | 先扫 `incongruity_cues`，再填 `rhetoric`（sarcasm / gaoji_hei / …） |

强制规则：`sentiment == intended_sentiment`。日报主指标用 `sentiment`，不把字面褒义当口碑。

## 2. 为何日报用 intended/sentiment + 单独 rhetoric 通道

- **监测要的是「玩家对游戏的整体态度」**，不是「这句话有没有褒义词」。
- 讽刺 / 高级黑若混进情绪主指标，要么漏掉阴损（当正），要么把亲昵吐槽打成负（误报）。
- 因此：**情绪结构看 sentiment；裂隙话术进「修辞复核」小节**，原话抽检，不升格为全站崩盘叙事。

可行动 `actionable` 与情绪解耦：整体可为正，但仍可标「是」供产品跟进。

## 3. 报告写法：四问、弱对照、滚动窗

写作框架（`04日报周报/skill.MD`）：

1. 发生了什么？（态势）  
2. 为什么会这样？（哪一簇、哪类诉求）  
3. 接下来可能怎样？（情景 + 触发条件）  
4. 建议怎么做？（角色 × 时机 × 动作）

执行摘要固定四句标签：【数据洞察】【热点追踪】【风险预警】【需要决策】。

样本纪律：

- 锚定日默认 = 库内**最新发布日**；n&lt;30 → 滚动近 3 个有数据自然日。  
- 对照窗 n&lt;30 或 &lt;0.5×本期 → **禁止 Δpp /「大幅异动」**，只报绝对水平。  
- 可行动 ≤3（日）/≤4（周），禁止摘录墙当正文。

终稿脚本：`build_skill_reports.py`（`*_sample_*` 仅为信息层半成品）。**日/周报主 KPI 只出 TapTap**，不把多渠百分比写进终稿。

## 5. 四渠道角色：为何 TapTap 主链 + 三对照

先跑通 TapTap 主链监测闭环，再扩展传播对照渠道。

| 渠道 | 角色 | 适合回答 | 不适合 |
|------|------|----------|--------|
| TapTap | 评价主链 | 是否推荐 / 是否继续玩；日周报 KPI | 二创梗、短视频即时热度 |
| B站 | 传播对照第一渠 | 视频场景在吵什么、是否与商店同向 | 直接当留存考核句 |
| 抖音 | 短视频对照 | 短梗与情绪化传播切片 | 全量历史 / 实时工单 |
| 微博 | 公开热议对照 | 话题切片里的围观与争议 | 全网热搜中台 |

纪律：跨渠道只比**结构与方向**（情绪构成、主题主簇是否同向）；样本不足时禁止 Δpp 叙事；对照渠比例不写进对标考核句。实现见 `06对照_B站/` · `07对照_抖音/` · `08对照_微博/`。

**采集边界**：抖音/微博风控高，仓库可能含 `fallback_seed` / `degraded_sample` 演示语料；`09跨渠道AI/facts_cross_channel.json` 与看板会标「降级」。

## 6. 跨渠道 AI：facts 锁数 + LLM 综合

旗舰产出在 `09跨渠道AI/`：

1. **`build_channel_facts.py`**：四渠 n / 情绪% / 主题 Top / 修辞 / 原话 id——**数字只来自代码**。  
2. **`synthesize_cross_channel.py`**：DeepSeek 高 reasoning，输入仅 facts；输出综合简报四句、渠道人设、值班建议、议题对齐表。  
3. **自检**：正文引用的 n/% 必须能在 facts.allowed_numbers 找回，否则重试或模板降级。

跨渠重点是议题对齐（同一槽点在哪些渠道出现），而不是再堆一张饼图。

## 7. 一句话收束

结构化标注把「字面 / 意图 / 修辞」拆开，报告写满「信息 → 判断 → 建议」，看板呈现摘要、四渠矩阵与可行动清单——主链在 TapTap，三渠做传播对照，跨渠道 AI 做议题综合。
