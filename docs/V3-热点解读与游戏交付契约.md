# V3 下一阶段：热点解读与游戏交付契约

当前版本：`3.0.0-alpha.10`。最新实现与非线性业务边界见[研究工具、时效与自动队列](V3-研究工具与自动队列.md)；下方旧版本段落保留对应时点记录，以最新契约为准。

日期：2026-10-08。状态：完整产品边界与实现目标；Alpha 9 已落地主 Agent、所属研究子 Agent 和部分交付/展示，实际完成范围见[实现与验收](V3-主Agent与研究子Agent.md)，下文全部验收要求尚未完成。本文记录用户对展示、自动化、情报和素材的最新定义，优先于旧设计中泛领域情报直接进入情报档案的口径。借用 GraphRAG 的抽取、关联、分层归纳和溯源思想；不以安装 GraphRAG 框架作为完成条件。

## 产品输出与后台过程

系统自动完成五个环节：热点发现、热点解读、游戏情报、可用素材、TapTap 增长创意。用户消费成果，可以展开依据、核查原文、纠正对象或判断；正常流程无需用户逐条选择话题或点击研究。

2026-10-08 架构修订：这些环节代表处理阶段和产品数据类型，不对应五个独立 Agent。最新确认采用一个业务主 Agent 和其所属的联网研究子 Agent。主 Agent 判断机会、整理游戏情报、提炼素材并制作增长创意；发现缺口时委派研究子 Agent 取证，接收返回结果后继续判断。程序承载调度、预算、校验、状态和恢复，不替代主 Agent 的业务决策。

热点覆盖不同领域。默认展示经过筛选和整理的标题与一句话事件摘要；点击查看背景、核心、主体、时间线、最新变化、有依据的讨论与争议。单个普通帖子、原始数字标题、新闻发布和热搜榜上出现分别处理，不因采集成功就称为热点。原文与运行记录放在核查入口，不承担事件说明的工作。

游戏情报记录对游戏、玩家或 TapTap 有意义的新变化与潜在线索。素材交付能被创作人员使用、改编或制作的表达与形式。增长创意直接依据近期热点与增长机会，也可使用已有情报和素材，说明吸引谁、传播什么、怎样进入 TapTap、引导什么动作、如何制作和验证。泛社会事件的背景归入热点解读；仅含链接或未经转化的内容引用归入来源资料。

## 最小执行架构

程序调度器管理阶段、依赖、预算、版本、缓存、重试和入库。业务主 Agent 决定候选是否值得跟进、还需什么证据、怎样提炼情报与素材、是否形成创意。联网研究子 Agent 按主 Agent 的任务补充事实与解读，再返回主 Agent。来源、事件、情报、素材和创意通过稳定编号及版本关联，两个角色共享证据存储，程序控制读写与资源边界。

| 执行单元 | 实现方式 | 边界 |
|---|---|---|
| 采集、清洗、重复识别、召回 | 来源连接器与程序算法 | 无需为每个渠道建立 Agent |
| 候选筛选与业务计划 | 主 Agent 根据规则预筛后的候选作结构化决策 | 决定研究、直接分析、观察或归档，提出具体证据需求 |
| 联网研究与热点解读 | 主 Agent 所属的一个研究子 Agent，按事件建立有预算的任务 | 根据委派问题选择检索、正文读取与讨论采样，返回解读、证据和缺口 |
| 游戏情报与素材整理 | 主 Agent 使用共享证据与子 Agent 的返回结果 | 同一角色产出不同数据对象，分别校验和入库 |
| 增长创意 | 主 Agent 决定机会是否值得做，并完成规划与制作 | 复用情报与素材；发现影响判断的新缺口时可再次委派研究 |
| 来源核对、入库和更新传播 | 程序处理，疑难语义判断按需使用模型任务 | JSON 合格仅是格式门槛，仍需核对引用、事实范围和业务条件 |

研究子 Agent 返回 `interpretation`、来源引用、读取范围与 `unresolved_questions`。主 Agent 读取这些成果与业务条件，初始优先把游戏信号、素材整理和机会判断放进一次结构化业务分析，分别返回 `game_signals[]`、`materials[]` 和 `opportunity_decision`。情报或素材允许空数组；程序分别验证各部分，并记录未通过部分的状态，不能因部分成功就宣称整个事件已完成。公共事实和表达依据可以复用，业务影响判断与改编内容仍须标明其推测或创作性质。

主 Agent 判断有有效机会后继续生成增长创意，避免无机会话题也消耗制作预算。可沿用已实现的方案规划、文案/脚本制作与草稿恢复，按实际输出长度决定是否分次交付；这些调用属于同一个主 Agent 的工作阶段。若业务分析确实因输入过大、失败重试或更新频率不同产生额外成本，再按该理由拆成可独立重试的模型任务，仍属于同一主 Agent，复用同一工作流与模型接口。

子 Agent 的自主性用于未知的取证路径：下一步查什么、读哪篇、是否需要补来源。主 Agent 的自主性用于游戏情报、可用素材与增长机会的业务判断，能够依据研究返回结果改变原判断。程序限定两个角色的可用工具、总预算与停止条件，持久保存任务、证据及缺口。来源足够时主 Agent 可以不委派研究；任务中断后由保存的状态续接，不要求保留无边界的聊天历史。

GraphRAG 思想对应证据抽取、事件关联、主题归纳与检索模块。图、聚类结果、事件解读和社群总结均为共享数据或模型任务成果，不为每个节点、事件或社群各建一个 Agent。算法召回与事件关系确认分别处理，模型总结不能替代来源核对。

## 阶段 1：广泛采集与低成本筛选

采集已经接入的公开热搜、榜单与热门频道，同时保留失败、覆盖范围和榜单观察。不承诺字面意义的全网完整覆盖。游戏资讯或社区帖子可形成情报线索，但进入热点展示仍需要可解释的事件和热度依据。

先在程序中去除重复记录、清理标题和链接、区分原始内容与转载；对信息不足的内容保留待补语境状态。不要把“8888”改成“玩家热议8888”来假装已完成理解。

随后使用小批次模型筛选，只传标题、来源类型、必要摘要与实际热度信号。逐条交付候选引用、类别、理由、缺口和检索词，引用必须对应输入记录，不允许创造平台、游戏名或传播量。类别为：

| 类别 | 后续动作 |
|---|---|
| 游戏直接相关 | 优先进入联网研究；区分热门事件与游戏动态 |
| 通用传播表达 | 优先研究表达本体、传播依据及可迁移的内容形式 |
| 其他领域潜在可转化 | 保留候选，使用独立且较小的探索预算；有合理迁移依据后升级 |
| 暂无合理联系 | 保存筛选记录，本轮不投入深度研究 |
| 信息不足 | 自动补必要语境，或保留待研究；不直接生成热点解读或创意 |

“游戏相关”不能仅由来源是 TapTap 判定；“通用爆火梗”不能仅由模型觉得有趣判定。来源给出了表达，但未证明广泛传播时，先记录待核实表达。筛选前保持跨领域采集，筛选后控制深度研究成本；此项取代旧设计中所有领域线索同等进入昂贵研究的处理口径。

## 阶段 2：按需联网研究与热点解读

这是主 Agent 所属的研究子 Agent，接收候选、已有来源、主 Agent 的研究问题和预算。规划查询词并调用真实联网搜索，读取结果中相关报道，必要时读取官方说明、公开讨论与后续报道；按来源主体、事件对象和时间排除同名不同事、旧闻、无关背景与转载。返回有来源的热点解读、证据和仍未解决的缺口，由主 Agent 判断如何使用。来源已经充分时主 Agent 可以不委派取证。

建议初始单题预算为两次检索、三篇正文、已支持平台最多二十条评论；具体调用上限、单次等待、响应大小与总任务时间由程序执行，模型不能自行扩大。浏览器搜索或正文读取遇到登录、验证码、平台拒绝或找不到可靠内容时保存真实失败和缺口，不伪造资料。现有仅单一媒体的新闻检索尚不满足这一能力，需新增通用公开网页检索与对应读取实现。

研究子 Agent 的热点解读交付：

- `headline`：一句让用户知道“谁发生了什么”的标题；对象未知时不能补造。
- `one_line`：具体变化或讨论核心，用一句话说明。
- `event`：主体、动作、对象、地点、发生时间及其精度；未知值为空。
- `background` / `core`：背景与核心经过的来源引用。
- `timeline[]`：节点、时间、时间依据和来源；分别标明事件时间、报道时间和采集时间。
- `discussion[]`：观点、出处和样本类型。真实评论、报道转述、模型推断分别标明。
- `controversies[]`：来源有依据的质疑或冲突；不存在证据时允许空，不凑正反双方。
- `heat_evidence[]`：实际榜单出现、同榜变化、传播观察；搜索返回量不能当讨论量。
- `unknowns[]`：未读正文、未取得评论、未确认热度等实际缺口。
- `claims[]` / `entities[]`：后续事件关联和溯源使用的主张与实体记录。

每个事实、时间节点和观点都引用输入的来源片段。程序分配稳定记录编号，并保存原文版本与片段位置；模型交付源内引用，不能自行杜撰来源编号。抽取到的来源主张不自动升级为已证实事实。仅能识别标题而无法补得足够语境时，交付为“解读待补证据”，不能显示成完整解读。

事件归属依据主体、动作、对象和时间判断。相同事件更新版本，独立发生的后续动作形成关联事件；主题社群归纳多个事件的共同方向，不直接决定事件合并。图结构服务关联与核查，用户默认看到标题和解读。

## 阶段 3：游戏情报数据契约

主 Agent 读取子 Agent 返回的解读、经过核对的事件证据、真实讨论、游戏与平台已知信息、历史情报，以及业务目标。先识别游戏直接相关的变化；通用或其他领域表达需要解释与玩家场景的具体联系。缺少联系时保留在热点解读/候选层，不靠在摘要末尾加上 TapTap 就计为情报。此项与素材可同次生成、分别校验和保存，不另建一个情报 Agent。

独立数据对象：`signal_title`、`game_or_player_context`、`observed_change`、`observed_at`、`evidence_refs`、`why_it_matters`、`relevance_route`、`hypothesis`、`unknowns`、`next_watch_trigger`。

情报是风吹草动，例如玩家表达方式改变、某种玩法需求出现、版本/社区问题或一种可迁移表达开始进入玩家语境。已经观察到的变化和对未来影响的推测分开。没有足够机会制作创意时仍可保存有效游戏情报并持续观察；不能把“继续观察”变成每次无条件重跑同样输入。

## 阶段 4：可用素材数据契约

主 Agent 读取热点的实际表达、子 Agent 的研究结果、游戏条件及既有素材；提取或转换出可用于游戏内容的东西。素材独立保存，不依赖增长创意完成后才积累，也不强制先生成一条游戏情报。可以有有效素材而暂无情报，有有效情报而暂无素材；独立数据与保存规则不等于单独的 Agent。

素材分为游戏原生素材和转化素材。原生素材包括有来源的玩家用语、可制作的游戏场景/形式参考等；转化素材把通用或其他领域的表达变成具体玩家场景中的句式、创意形式或制作方案。未经转化的社会新闻摘要只保留为背景资料。

每项素材必须交付：`material_type`、`content_or_template`、`game_application`、`usage_example`、`format`、`basis_refs`、`origin`、`usage_conditions`、`production_status`。

来源摘录逐字校验；表达模式标为分析推断；改编内容标为原创或改编草案，并保留其来源依据。一个媒体地址属于媒体参考，不等于已经取得图片、视频或转录内容；制作方案也不等于制作成品。素材不能只写“适用于游戏营销”，需要具体说明适用的玩家场景、改编方法和表达实例。无可用素材时允许空输出并记录原因。

素材按表达方式、参与机制、情绪、使用场景和内容形式检索与归组，事件编号只作为来源关联。多个事件可复用同一种表达机制，同时保留不同版本、来源和使用条件。

## 阶段 5：按条件生成增长创意

这是主 Agent 依据机会判断执行的结构化生成任务，不启动一个独立创意 Agent。输入有效游戏情报、实际可用素材和 TapTap 业务条件。组合成可执行方案：受众、增长目标、创意吸引点、传播方式、进入 TapTap 的承接路径、目标用户动作、素材引用、文案、脚本/视觉制作方案、执行步骤、所需资源和小规模验证方法。

必须说明“依据哪条情报、使用哪项素材、为何这个人群愿意参与或传播”。未确认的资源位、活动功能、游戏能力和奖励明确为待确认条件，不能写成已存在。增长假设尚未验证，不把拟定点击率或增长效果当成实际结果。

不为每个热点强行生成创意。可以保留游戏情报或素材，等待时机与条件；值得测试且具备完整交付时保存创意。业务校验除 JSON 格式外，还要核对来源、玩家场景、素材适用性和具体承接动作。

## 自动运行、核查与纠错

程序调度器自动安排上述阶段，保存输入指纹、任务状态、已完成阶段、失败、重试条件与调用预算。热点解读以来源版本作为缓存依据；游戏情报、转化素材和创意同时绑定业务条件版本。联合调用的各部分仍分别保存依赖版本，业务条件改变时复用未改变的事件证据和解读，按需安排业务部分更新任务，不重跑联网研究。新来源或新变化只使相关结果进入更新任务；相同输入复用，避免每轮全部重做。

正文、搜索、讨论和模型能力不足时明确展示阶段缺口，不计为五阶段完成。研究补得证据后自动接续。普通情况自动处理，人工判断用于异常纠正、语义边界复核及执行创意的决定。

用户从创意、素材、情报或解读的任一结论都能直达依据与原文版本，不必依次打开所有页面。纠错保存原结论、用户修正和重新核查结果；对象或来源纠正后标记受影响的下游交付待更新，不能只改页面标题而继续使用旧依据。

## 第一轮验收要求

1. 普通数字标题不会直接进入默认热点展示，也不会被 AI 凭空改写成“玩家热议”。
2. 游戏直接相关、通用表达和其他可转化候选分流可检查，昂贵联网研究发生在筛选之后。
3. 每个展示项都有读得懂的标题、一句话核心和实际热度范围；点击看到解读，原文位于核查入口。
4. 联网研究使用真实查询和读取记录，时间线、讨论、质疑的每项都有来源，缺失可空。
5. 泛领域解读、游戏情报、可用素材分开计数与展示；链接不计制作成品，表达模式不计真实玩家意见。
6. 一个具有合理游戏联系的实际话题无需人工逐阶段点击，能进入情报、素材及具备条件的创意交付；无合理机会时保留正确阶段和原因。
7. 用户能从任一创意关键判断核查来源，纠错后受影响下游可自动更新。
8. 连续自动周期保存新增、变化、失败、成本与已交付成果，不能仅以一次手动任务成功宣称自动化完成。
9. 五个产品环节不各自建立 Agent；主 Agent 负责三类业务成果，研究子 Agent 接收委派并返回解读和证据，程序控制预算及校验，三者边界可从运行记录核查。

上述均为后续实现与验收目标，本文和契约的存在不代表这些能力已落地。
