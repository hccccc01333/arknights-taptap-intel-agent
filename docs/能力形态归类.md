# 能力形态归类 —— 哪些是工具、哪些是记忆、哪些是缓存

> 建档：2026-09-30。**这是「分工架构设计完之后」的收口文档。**
> 决策人：HZZ；agent 只做实现、验证与边界汇报。
> 上游：[Agent框架落地设计](./Agent框架落地设计.md) · [热点追踪设计](./热点追踪设计.md) · [素材层设计](./素材层设计.md)
> 定位：把散在各设计文档里的资产**统一归类一次**，定清「工具 / 记忆 / 缓存 / 流程」四种形态，
> 并回答三个「要不要」：向量库 · MCP · 子 Agent。

## 0. 为什么需要这次归类

用户 2026-09-30 指出：

> 「包括 MCP、Skill、Memory、子 Agent 的设计，这些架构设计好之后，
> 无非就是**分好类，哪些是工具？哪些是放在记忆里面的？**
> 然后**要不要建这个 RAG 的文本向量数据库？** 这些就可以进行讨论了。」

**对。** 之前每份文档各自讲自己那块，但**没有一张表把「这东西属于什么形态」列清楚**。
后果是具体的：

- 容易把**可重算的缓存**当记忆（浪费、且会不一致）
- 容易把**分析模块**当工具（其实 Agent 不决定调不调）
- 容易在**还不需要**的时候就上向量库 / MCP（徒增复杂度）

## 1. 四种形态的判据（★ 新增资产时按这个判）

| 形态 | 判据（一句话） | 关键问题 |
|---|---|---|
| **Tool** | Agent 拥有「**要不要调、调几次、传什么参**」的决策权 | 这是不是 Agent 的**选择**？ |
| **facts 源** | Agent **不决定**，编排里固定跑；输出是 Agent 的**输入** | 这是不是 Agent 的**食粮**？ |
| **Memory** | 跨运行必须保留，且**删了无法从原始数据重建** | 删了还能重算吗？ |
| **缓存** | 可重算——删了重跑就有 | （同上，能重算就是缓存） |

> **★ 最有价值的一条是 Memory vs 缓存的判据**：
> **问「删了它，能不能从原始数据重建」——能就是缓存，不能才是记忆。**
>
> 反例说明为什么重要：`outputs/risk_insight.json` 看着像"系统的记忆"，
> 但它**删了重跑脚本就回来了** → 它是**缓存**。
> 而 `topic_state` 的**状态迁移历史**删了，要重放全部历史采样才能重建 ——
> 而且如果采样数据已丢，**就永久丢失了** → 它才是**记忆**。

> 这就是为什么它们必须是 Memory 而不是缓存。

### 2.4 缓存（可重算，删了重跑就有）

| 资产 | 位置 | 为什么是缓存 |
|---|---|---|
| `outputs/*.json`（facts） | `data/outputs/agent/` | 重跑对应脚本即可重建 |
| `reports/*.md` | `11情报Agent/reports/` | 同上 |
| `outputs/community_ops.json` | 同上 | 同上 |
| 爬虫的 `raw/` 落盘 | `data/raw/taptap/raw/` | ⚠️ **例外**：见下 |

⚠️ **一个必须说的例外：爬虫原始数据不是纯缓存。**
因为**「当时的快照」不可复现** —— 今天重爬，点赞数、评论数、甚至帖子是否存在都变了。
所以 `data/raw/taptap/raw/` 与 `discovery_*.csv` 属于**「一次性证据」**：
**技术上可重爬，但重爬得到的是不同的东西。**

**结论**：这类数据要**归档保留**（且属原始域、不入库），
不能按"反正能重算"就删掉。**这是本次归类发现的一个容易踩的坑。**

## 3. 三个「要不要」的判断

### 3.1 要不要建 RAG / 向量数据库？ → **现在不建，留接口位**

**先看哪些场景真的需要语义检索**（全项目只有三处）：

| 场景 | 需要语义检索吗 | 替代方案 | 结论 |
|---|---|---|---|
| 仲裁层**样例检索**（判"是不是梗"） | ⚠️ 样例库 >100 条时才需要 | **按结构分桶取 K 条**（few-shot） | 首批不建 |
| **历史相似素材**（含突发响应的"像不像上次那个事"） | ✅ 是 | — | 等素材库有量再建 |
| **跨源对齐**（"三角洲行动二周年" vs "三角洲二周年"） | ⚠️ 可不用 | **编辑距离 / 字符 n-gram 相似度**（纯标准库） | **先用轻量方法** |

**为什么不现在建**：
1. **素材库现在是 0 条** —— 向量库没有可以索引的东西
2. **embedding 本身要花钱或要下载模型**（DeepSeek 余额还 402）
3. **跨源对齐有更便宜的解法**：编辑距离/字符相似度就能处理大部分中文简称问题，
   不必为了"看起来像 RAG"就上向量库

**触发条件（什么时候该建）**：

| 指标 | 阈值 |
|---|---|
| 素材库规模 | > 500 条 |
| 样例库规模 | > 100 条 |
| 或者：轻量方法实测**召回明显不足**（要对不上号） | 实测驱动 |

> **一句话**：**向量库是解法，不是目标。** 现在的问题（0 条素材）不是向量库能解决的，
> 而是**先把素材抽出来**。等有了数据，用轻量方法先跑；跑不动了再上向量库。

### 3.2 要不要引入 MCP？ → **现在不引入，但边界已天然存在**

**判据**：工具是否需要**跨进程 / 跨语言 / 被外部系统调用**。

| 现状 | 判断 |
|---|---|
| 单机、单进程、Python | ❌ 不需要 MCP —— 进程内直调更简单、更可调试 |
| 但 `SourceAdapter` 设计 | ✅ **它就是 MCP server 的现成边界**（一个 adapter = 一个 server 的 tool 集） |

**触发条件**：当工具需要被**别的 Agent / 别的语言的服务**调用时再包 MCP。
在那之前引入 MCP 只会增加进程管理与协议调试的成本，**没有任何收益**。

> **注意区分「好设计」和「现在要建」**：用户说的"都好设计"是对的——
> **边界留好就够，不必现在实现。**

### 3.3 要不要拆子 Agent？ → **现在不拆，但按「可独立演进」设计**

**子 Agent 的意义**是：**独立上下文 + 独立失败隔离**。

| 现状 | 判断 |
|---|---|
| LangGraph 4 图（巡检/情报/追踪/创意） | 已按"每图独立 state + 独立 DB"设计 |
| 单机单进程 | ❌ 不需要拆子 Agent |

**触发条件**：
- 某张图的执行时间/成本**显著超过**其他图（需要独立并发）
- 或某张图需要**不同的权限/凭据**（如推送需要 webhook 凭据，分析不需要）

**在那之前**：4 张图跑在一个进程里，**但每张图有自己的 State 定义和自己的存储** ——
这就是"可独立演进"的含义：**将来要拆，只是把图搬到另一个进程，不用改逻辑。**

## 4. Skill 的角色：流程知识，不是事实也不是工具

**Skill 与 Memory 的区别**：

| | 存什么 | 例子 |
|---|---|---|
| **Memory** | **事实与状态** | "话题 X 现在是爆发状态" |
| **Skill** | **流程与方法** | "加一个新源要改哪几个文件" |

**现有 5 个 Skill**（`skills/` 是唯一源目录）：

| Skill | 承载的流程知识 |
|---|---|
| `arknights-taptap-crawl` | 爬虫字段契约 |
| `arknights-llm-annotate-v14` | 标注两段式 |
| `arknights-taptap-yuqing-report` | 日/周报写法 |
| `arknights-cross-channel-facts` | 跨渠 facts 锁数 |
| `arknights-daily-intel-agent` | 每日情报 Agent |

**本次归类指出的、将来值得沉淀为 Skill 的流程**：

| 候选 Skill | 对应流程 |
|---|---|
| 加一个新数据源 | 改哪些文件、怎么验（`SourceAdapter` 落地后） |
| 阈值校准 | 怎么用 `ops_action` 反推阈值 |
| 发布一个新角色模块 | 社区运营模块的落地步骤（可复用） |

## 5. 归类结果速查（给未来的自己）

新增任何资产时，按顺序问四个问题：

```
Q1 这是 Agent 的「选择」还是「食粮」？
     └ Agent 决定调不调 → Tool
     └ 编排固定跑、产出给 Agent 读 → facts 源

Q2 删了它，能从原始数据重建吗？
     └ 能 → 缓存（可以随便删）
     └ 不能 → Memory（★ 要备份、要入库策略、要考虑 PII）

Q3 需要按语义找相似的东西吗？
     └ 需要且量级够（素材>500 / 样例>100）→ 才考虑向量库

Q4 需要被进程外/别的语言调用吗？
     └ 需要 → 才考虑包 MCP
```
