# 第六层前端设计体系 —— Spatial Intelligence Interface

> 定位：把[应用决策执行层设计](应用决策执行层设计.md) §25-§47 的 Growth Intelligence Operating System
> 落到可实现的交互形态。核心理念：**Signals → Intelligence → Assets → Growth Ideas → Execution**。
>
> 参照：Bruno Simon 的可玩式导航、Lusion 的 3D+DOM 统一叙事、Active Theory 的沉浸式信息旅程。
> 不做 SaaS Dashboard，不做 Admin Template。
>
> **本文件先行，实现随后。** 下面是实现前必须定稿的设计体系（A–H）。

## 0. 两个前置事实（决定技术选型与数据映射）

| 事实 | 影响 |
|---|---|
| **环境无 Node/npm，也无 winget/choco** | Next.js + React Three Fiber 当前不可用。采用 **Three.js 直写（本地 vendor，零构建）**，由 FastAPI 直接静态托管。组件 API 会对齐 R3F 的写法，日后装 Node 可平滑迁移 |
| **真实数据形态与"宇宙"假设不匹配** | 211 个事件的热度集中在 0.133–0.358（中位 0.156）、势头中位=最小值、生命周期只有 2 段、199/211 是 TapTap 单平台、相关性只有 2 个事件 |

**结论：宇宙必须由 L2 的 3811 条真实内容撑起，而不是由 L3 的事件分数撑起。**
数据映射每一条都标注「真数据」还是「诚实降级」（见 §C）。

## A. 产品视觉概念

### A1. 一句话

**打开时是一张正在运转的游戏世界星图；每个亮点都是一处正在发生的真实讨论；TapTap 是星图的引力中心，
离它越近的事，越值得我们动手。**

### A2. 五层空间结构（不是页面层级，是空间层级）

```
Universe      全网星图：所有话题作为星球，TapTap Core 在中心
  └ Cluster    语义相近的星球聚成星团（引力井视觉）
      └ Topic 单颗星球 = 一个话题（fly-in 进入）
          └ Inside  话题内部：信号粒子、平台管道、评论气泡、质量表面
              └ Idea  增长创意卫星（绕星球公转，可点开做出来）
```

### A3. 视觉基调

- 底色 `#06070A`（不是纯黑）；深空感来自**明度层次**，不是霓虹
- 高亮色只给五种语义：爆发 / 机会 / 进行中 / AI 洞察 / 风险
- 高级感来自比例、空间、光照、材质克制、**运动有语义**

### A4. 与当前"数据陈列馆"的根本区别

| | 当前版本 | 本设计 |
|---|---|---|
| 第一眼 | 40 张卡片 | 哪里在亮、哪里在靠近我们 |
| 数值角色 | 主角 | 配角（悬停/选中才出现） |
| 导航 | Tab 切换 | 相机推进（保留效率通道） |
| 结论 | 数据告诉你发生了什么 | 空间告诉你**我们该做什么** |

## C. 3D 数据映射系统（每条标注真数据 / 诚实降级）

### C1. 星球（Topic Planet）

| 视觉维度 | 数据来源 | 状态 | 说明 |
|---|---|---|---|
| **半径** | L3 `hot_score` | ⚠️ **百分位映射** | 线性映射会让 211 颗球几乎一样大（真实 0.133–0.358）。改 rank-based：`r = rMin + (rMax-rMin)·rank/n` |
| **光晕 / 脉冲** | L3 `momentum_score` | ⚠️ **百分位映射** | 势头中位=最小值，绝对值不可视，只有相对排名有意义 |
| **到 Core 距离** | L4 `relevance` | ❌ **缺数据（2/211）** | 三级降级见 C2 |
| **粒子密度** | L3 `content_count` | ✅ 真数据但极度倾斜 | 中位=1、max=629 → 用 `log(1+n)`，否则一颗 629 颗粒子其他 1 颗 |
| **表面材质** | L2 `quality_score` / `spam_score` | ⚠️ **代理值，非情绪** | 「内容干净度」：干净=平滑稳定，spam 高=噪点。**不冒充情绪** |
| **自转速度** | 生命周期 | ✅ | EMERGING 慢→快；DECLINING 停滞 |
| **标签** | `canonical_title` | ✅ | DOM 标签，不用贴图文字 |

### C2. TapTap 引力场：缺失数据的诚实处理

**问题**：设计稿核心命题是「外部已爆发、TapTap 还没跟上」（Opportunity Gap），但 relevance 只有 2 个事件。

| 级别 | 计算方式 | 视觉标注 |
|---|---|---|
| L1 真实 | L4 已分析的 `relevance` | 实线 + 标签 |
| L2 代理 | 事件实体是否命中 `games/*.json`（`game_*` 标签）+ 该事件内容的 `gaming_probability` 均值 | 虚线 + 「按游戏档案推测」角标 |
| L3 未知 | 无任何匹配 | 外圈轨道 + 「与我们关系未知」 |

**绝不允许**：把缺失当 0（撒谎），或用热度冒充相关性。

### C3. Signal Pipes（信号管道）

真实管道只有 4 条：taptap 3303 / bilibili 455 / weibo 43 / douyin 10 条内容。

| 视觉维度 | 数据 | 状态 |
|---|---|---|
| 管道粗细 | 该平台对该事件的内容量 | ✅ 真数据 |
| 流动速度 | `momentum_score`（百分位） | ⚠️ 降级 |
| 管道脉冲 | 平台新增内容（需快照，当前不可得） | ❌ 等连续采集 |

**诚实说明**：只有 12/211 事件有跨平台管道，宇宙里大部分星球只有一条管道 —— 这是数据现状。
「多管道同时涌入」要做成未来的**高光时刻**，现在它是空的。

### C4. 要让 Opportunity Gap 成立，必须补的数据

```
① 事件级 × 平台级内容量矩阵（现在只有事件级聚合）
   → 才能算：外部热度高 + TapTap 讨论低 = Gap
② 事件级 relevance（现在 2/211）
   → 批量跑 L4 Relevance，或先用 C2 的 L2 代理跑一轮
③ 时间序列（event_score_history 每事件仅 1 条）
   → 连续采集 2 周后才有传播动画的素材
```

## D. 主要用户路径

```
D1 发现（默认）
   打开 → 星图缓慢自转 → 右下角 AI 建议「2 小时内创建 X 话题」
   → 点建议 → 相机锁定该星球并高亮 → 右侧展开「为什么该做」
   → 点星球 → Camera Fly-in → 话题内部（信号/评论/质量表面）

D2 决策
   话题内部 → 右侧「为什么是 TapTap」→ [跟进] [指派] [生成方案]
   → Growth Idea 卫星出现 → 点开 → Idea Canvas → 补素材 → [排期上线]
   → Execution（Level 2：人工审批才上线）

D3 回溯（效率通道，随时可用，不做相机动画）
   ⌘K → 输入指令或搜话题 → 直接跳转
   面包屑：Universe / 星团 / 话题 / 创意
   Esc / 返回键：随时退出沉浸，回到 Universe
```

## F. Motion Language

### F1. 三段式（anticipation → movement → settle）

任何层级切换都不是 fadeIn/fadeOut：

```
1 anticipation  悬停 120ms：星球微微前倾 + 边缘提亮
2 movement      400–900ms：相机加速飞行（ease-in-out-cubic），其他物体降亮降饱和
3 settle        200–300ms：目标星球呼吸一次（scale 1→1.04→1），DOM 面板从下方 16px 升入
```

### F2. 时长表（克制，高频操作不许长动画）

| 场景 | 时长 |
|---|---|
| 悬停反馈 | 120–180ms |
| 面板展开 | 250–400ms |
| 焦点切换（Topic→Inside） | 600–900ms |
| 相机飞行（Universe→Topic） | 900–1400ms |
| 叙事级转场（进入 Growth Lab） | ≤1800ms，且只播一次 |

### F3. 持续运动（克制，且都有语义）

| 运动 | 语义 |
|---|---|
| 星球自转 | 生命周期（起势 = 慢且提速；降温 = 停滞） |
| 管道粒子流 | 该平台的信号流入速度 |
| 光晕呼吸 | 势头（百分位越高，脉冲越明显） |
| Core 缓慢脉动 | TapTap 引力场存在感的锚点，不承载数据 |
| 相机微视差 | 指针移动，幅度 ≤2%（防晕动） |

### F4. 无障碍

`prefers-reduced-motion` → 所有飞行降级为 150ms 淡入，粒子静止，自转停止。
键盘：Tab 遍历星球（焦点环可见），Enter 进入，Esc 退出，⌘K 指令面板。

## G. 组件架构（无构建 · Three.js 直写）

### G1. 技术选型决策

```
不用：Next.js / React / R3F   —— 环境无 Node；且业务后端是 Python，
                                R3F 的收益（组件化/状态）可用原生 ESM 拿到
用：  Three.js（本地 vendor ESM，零构建）+ 原生 ESM 模块 + 一个微型状态容器
     FastAPI 继续托管静态文件（与现有 webapp 同一套 API 与权限）
迁移：组件 API 按 R3F 习惯写（props 单一对象、生命周期钩子），日后可包一层迁 R3F
```

### G2. 目录

```
webapp/static/spatial/
├── index.mjs            入口：挂载 canvas + DOM 浮层 + 状态容器
├── core/
│   ├── renderer.mjs      WebGLRenderer、尺寸、自适应、像素比上限
│   ├── camera.mjs        相机状态机（UNIVERSE/CLUSTER/TOPIC/INSIDE/IDEA）+ 补间
│   ├── scene.mjs         场景、雾、光照（三点光 + 环境光 + Rim）
│   ├── loop.mjs          渲染循环、delta、可见性暂停（切后台不烧 CPU）
│   └── tokens.mjs        §E 的 token（唯一真源，CSS 变量与 JS 共用）
├── world/
│   ├── core.mjs          TapTap Core（引力中心）
│   ├── planet.mjs        TopicPlanet：半径/光晕/自转/表面材质（全映射规则在这）
│   ├── cluster.mjs       语义星团（引力井）
│   ├── pipe.mjs          SignalPipe：粗细/流速/粒子
│   ├── particle.mjs      信号粒子（log 密度）
│   ├── idea.mjs          GrowthIdeaSatellite
│   └── propagation.mjs   传播路径（等时间序列数据到位后启用）
├── ui/                   （DOM 浮层，纯展示与操作）
│   ├── filter.mjs  today.mjs  topic.mjs  ideacanvas.mjs
│   ├── palette.mjs  breadcrumb.mjs  toast.mjs  settings.mjs
├── data/
│   ├── api.mjs           复用 /api（同一套权限）
│   ├── mapping.mjs       §C 的映射规则（纯函数，可单测）
│   └── degrade.mjs       降级标记（L1/L2/L3、角标文案）
└── store.mjs             极小状态容器（选中/悬停/筛选/相机状态）
```

### G3. 分层纪律

- `mapping.mjs` 是**纯函数**：`topic → {radius, glow, density, position, degradeFlags}`
  ——可单测，不碰 Three.js。数据映射规则（百分位、log、降级）全在这里，不散落各组件。
- 3D 只画 World：空间、关系、流动、层级。所有文字/按钮/输入走 DOM。
- 业务状态不存 3D 层；`store.mjs` 是唯一真源，3D 每帧从中读只读快照。

## I. 实现前需要拍板的三件事

1. **技术栈**：Three.js 零构建（本方案） vs 先装 Node 再上 R3F
2. **数据补齐优先级**：先跑 L4 Relevance 批量补相关性，还是先做事件×平台矩阵补 Opportunity Gap
3. **MVP 范围**：只做 Phase 1 的 Universe + Topic Inside，还是同时做 Growth Idea（Phase 4）
