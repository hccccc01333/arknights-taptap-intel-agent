## 0. 为什么需要这份清单

2026-09-30 用户质疑：

> 「我想看一下，当初我们的目标是『服务游戏社区，完成全网热点追踪，
> 构建 AI 自动化情报与素材系统，通过热点识别产出与 TapTap 相关的实际增长创意』。
> **你确定你目前这几层完成了这个东西了吗？**」

**答案是没有。** 而且问题出在我的盘点方式上：

| 我此前的视角 | 问题 |
|---|---|
| **系统视角**（七层：采集→数据→感知→资产→生成→行动→交付） | 层画全了，容易误以为"结构完整 ≈ 快完成" |
| **目标视角**（把目标原文逐词拆成可验证的验收项） | ✅ 这才是能回答"做完了没有"的方式 |

**两个视角的差别是致命的**：七层里 ①②③ 我都标了"已跑通"，
但目标里的动词（**服务、追踪、自动化、产出**）恰恰全落在标 ④⑤⑥⑦ 的地方。

> **一句话教训**：**结构完整不等于目标达成。** 盘点必须对着目标原文，不是对着自己画的架构图。

## 2. 结构性偏差（这份清单最重要的产出）

看清单能发现一个模式，比数字本身更值得警惕：

| 类别 | 项 |
|---|---|
| **做成的** | 热点识别、情报判断、追踪机制 —— **都是"算得对"** |
| **没做成的** | 服务、全网、自动化、素材、触发、产出、采纳 —— **都是"送得出"** |

> **偏差：我把两个月的精力放在了"让数字算得对"，而目标是"让情报有用"。**

**但要公平地说**：感知层不是白做的。没有算得对的情报，后面的创意就是空中楼阁——
**问题不是做错了，是顺序上偏了，而且偏了很久没察觉**（因为一直用系统视角盘点）。

## 3. 由此得到的优先级修正

### 修正前（我之前的建议）
批 1 素材层 → 批 0 样例库 → 批 2 梗/二创

### 修正后（按验收项缺口排）
| 优先 | 做什么 | 补哪个验收项 | 依赖 |
|---|---|---|---|
| **1** | **可插拔推送层**（企微 / 飞书 / 微信，配置决定启用哪个） | **A1**（服务到人） | 无（不依赖 LLM/余额） |
| **2** | **定时调度**（无人值守跑通全链） | **B1**（自动化） | 推送层 |
| **3** | 素材层批 1（原帖引用 + 高赞候选池） | **B3**（素材） | 推送层（否则没出口） |
| 4 | 触发链接通（状态迁移 → 推送/素材） | **C1** | 素材层 |
| 5 | 二创生成 + 采纳反馈 | **C2 / C3** | 余额 + 样例库 |
| 6 | 第二个信号源（非 TapTap） | **A2**（全网） | — |
| 7 | 采样调度（心跳频率） | **A4**（追踪） | 调度层 |

**为什么把推送层排到第 1**：它同时是 A1 的正面命中 + 后面所有产出的出口。
**而且它不依赖任何未解的东西**（不需要 LLM、不需要余额、不需要新语料）。

## 4. 使用纪律

> ★ **2026-10-01 用户纠正（先读这条）**：本项目是 **Agent 开发项目**，
> **「服务到人」（交付层 / 推送 / 采纳入口）最后才建**。
> 本清单是**交付加权视角**，用途是检查「送得出」有没有缺口；
> **不要用它给 Agent 能力项排期** —— 用它排会把顺序排反（曾据此错误建议先做推送层而推迟突发响应框架）。
> 排 Agent 侧的优先级，尺子是**能力闭环：感知 → 决策 → 行动 → 校准**。
> 下面第 2 条纪律（「答不上来就不做」）**仅适用于交付侧功能**，不适用于 Agent 能力项。

1. **每次盘点必须对着这份清单**，不是对着架构图。
2. **新增功能时必须先问**：它让哪一项从 ❌ 变 ✅？（答不上来就不做）
   ⚠️ 仅限交付侧功能；Agent 能力项改用「它补的是能力闭环的哪一环」来问。
3. **不许用"层画完了"代替"目标达成了"** —— 这是本项目已经犯过一次的错。
4. 验收标准要**可验证**（"员工能收到"而不是"推送功能已开发"）。
