# V3 技术价值验证：LLM、搜索与完整 Agent

状态：实验工具与协议已建立，**真实模型对照尚未执行，没有准确率提升或增长效果结论**。
协议版本：`agent-benchmark-v1`。这是一项开发者研究，不在产品页面增加启动任务的按钮，也不改变后台全自动运行方式。

## 要回答的问题

在没有 TapTap 内部人员、运营数据和投放条件时，先验证系统是否降低事实、时间、引用和风险错误，以及额外成本是否值得。比较的是使用系统与不使用系统的区别。

| 组别 | 实际执行路径 | 主要比较 |
| --- | --- | --- |
| A：普通 LLM | 一次最终 JSON 回答，不联网，不经过生产日期、引用或风险程序校验 | 标题及有限初始信息能做到什么 |
| B：LLM＋搜索 | 固定用原标题搜索并有限读取网页，再由同一模型一次回答 | 收益是否主要来自联网资料 |
| C：完整系统 | 真实 `pipeline.process` → Main 筛选 → Research 计划与工具 → 解读 → 独立情报/素材判断 → 有条件的创意交付，使用现有契约、图谱、时效、风险和持久执行机制 | 额外研究与交付控制的收益和代价 |

A/B 并非刻意弱化的提示词：也要求分清时间、证据和假设，不虚构玩家态度、不借势负面事件，并提供和 C 相同的 TapTap 产品定位与能力边界。A/B 只有输出格式校验，不运行 C 的语义和交付守卫。C 使用现有生产提示词，不能借用额外模型修饰最终结果。

比较的是**整体执行策略**，并不能仅据 C 胜出断言“多 Agent 优于单 Agent”。生产结构只有业务主 Agent 和所属研究子 Agent，功能与 Agent 数量不是一一对应。

## 预先固定样本与条件

1. 从真实采集库以只读方式保存候选池，保留当时标题、URL、来源、原发布日期、观测时间、榜单位置与最多450字的初始片段。三组得到同一初始信息，不能只给 C 正文或隐藏日期。
2. 在运行模型前核查事件身份与时间，选择10件不同事件。至少覆盖 `new_event`、`old_or_revival`、`negative_or_disputed`、`incomplete` 四类。游戏相关与社会/娱乐/文化线索都应纳入，不能以方便读取或预期有利作为筛选依据。
3. “旧闻被今日抓到”是旧内容诊断样本，不能叫当天热点。没有近期传播证据的普通资讯也不能认证为热点。按病例选取的挑战集不代表全网自然分布，报告须写明每类数量和入选理由。
4. 为每件事件预先写必要事实、原文引句和 HTTPS 来源，保存在独立 `*-gold.json`；模型只能得到 `seed`，得不到类别、选择理由、核验基准或已有生产分析。这样覆盖率三组共用相同分母，也避免根据回答临时修改标准。
5. 先用另外两例校准连接、时延、输出长度和成本，不算入正式结果。正式样本不能复用校准案例。校准后如需改模型/提示词/代码，冻结新协议和正式批次再跑，保留原校准失败。
6. 初始计划是正式10例×3组×1轮，共30组结果。每个事件三组顺序用固定随机种子打乱，保存实际顺序；不是30个独立事件。一次生成有随机性，后续重复实验必须单独记录授权和协议。

冻结文件保存代码清单哈希、Git 提交、未提交差异指纹、产品档案、契约版本、样本及费用依据。文件不覆盖，代码或清单变化时拒绝继续；冻结超过24小时拒绝把旧样本继续当实时批次。

每组使用独立 SQLite、空的事件图谱与情报/素材库。C 不获得原有生产库的分析或已人工标注关系。这轮测冷启动的事实可靠性，不据此证明长期记忆、全网发现覆盖或聚类质量。

C在单次自动处理周期与已设研究预算内交付；当前研究计划最多进行两轮工具规划，未解决的问题和待补查记录保留。实验不跳过后续任务的正常退避去反复运行直到成功，因此不以这次单周期对照证明长期事件跟踪或补查效果。

## 搜索、证据与时间的公平性

B/C 都有每事件最多6个研究工具预算单位。B 采用固定原标题公开搜索，单次搜索及读取最多3单位；C 可以根据缺口选择检索、正文、评论、浏览器和截图。预算上限相同，实际使用量不同也记录。工具预算单位不是 HTTP 请求数，也不是金额。

V3 的公开 HTTP 路径记录原响应、解析前字节哈希、URL、获取时间和失败类型。同一事件的相同公开请求复用首次快照，B/C 对已命中的同一页面使用相同字节；不同检索词可能得到不同结果，这属于研究策略的差异。浏览器截图/OCR及旧版详情适配器另外保存最终来源片段、读取结果或截图文件，不声称所有网页都能回放。原文、HTTP快照和截图仅保存在本地忽略目录。

缓存复用会影响耗时，因此报告需同时看实际 HTTP、缓存命中、工具记录和模型耗时，不能把缓存受益直接解释为架构更快。记录真实检索时段，不用“抓取时间”替代“事件时间”；同一天也可能有事件进展与网页变化。

C 如果因缺少发布日期、正文、评论或可信来源而无法研究，必须保留这个漏处理和具体路径。不能在实验中补齐它的输入而不给 A/B，更不能挑选只会成功的样本。

## 模型、推理与费用

首批配置是 DeepSeek 官方 `deepseek-flash`，三组统一 `high`，每次总输出上限8192 token，包含推理。C 各阶段仍受真实生产阶段上限约束（例如研究计划4096）。请求与实际返回模型均留档；实际模型标识变化时停止，不混合计分，也不自动切换供应商。

预算方案待用户确认并充值：建议账户先充值20元，实验累计上限10元，其中两例校准累计上限2元。充值额不是计划全部消费，正式结果可能因为限额或服务问题不完整。

费用依据取2026-10-10核查的 [DeepSeek 官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)：Flash 高峰每百万未缓存输入2元、输出8元；闲时分别1元与4元。实验暂按更高价格估算，缓存优惠不计入预算释放，运行前再次核查。没有把供应商未知费用写成零。

每次模型请求前在独立 SQLite 短事务预留费用；输入用请求 UTF-8 字节数加4096框架余量作宽松 token 上界，输出取实际请求上限。该上界仅适用于已限定的官方 Flash 文本接口，不能套到图片、其他供应商或网关。授权配置固定接口/模型/强度/总输出参数。

模型返回 `usage` 后按输入和输出 token 结算；`reasoning_tokens` 已在输出中，**不再加一次**。截断、JSON错误、契约失败、格式修正和已收到的无效结果都计费。网络中断或未知用量保留全额预留并停止，不能以重试消耗未知余额。单组最多16次模型请求，费用上限独立于此次数限制。

记录的是高峰单价的**估算费用**，不是供应商账单。总耗时、搜索请求、浏览器/OCR资源和费用未知项分别报告；当地 CPU 时间不冒充 LLM 费用。正式组费用与校准费用分开，累计支出共同受10元上限控制。

授权记录只在收到用户确认充值完成、供应商和费用上限后建立。不会解除正式后台的额度暂停，不调用后台就绪探针，也不把实验模型加入生产设置。

## 怎样核验，而不是让模型互相打分

主要核验单位是每个事件的5项结果；逐条事实计数和必要事实覆盖率作为补充。完整阅读摘要、情报、素材与创意正文，不能只检查 `claims` 数组。引文能匹配不代表语义支持，更不证明总体用户需求。

| 项目 | 合格条件 | 常见错误 |
| --- | --- | --- |
| 关键事实 | 主体、行为、对象有可信来源支持，影响推测标为假设 | 换主体、把二手报道当官方承诺 |
| 事件日期 | 区分发生、报道、采集、旧内容近期传播；证据不足保持未知 | 将今天抓到的旧帖说成今日新事件 |
| 引用支持 | URL可定位、引句存在并实际支持结论，完整记录来源范围 | 引文存在但与该断言无关 |
| 无依据断言 | 不编造热度、玩家态度、比例、游戏能力或承接入口 | 从少数评论推断全体玩家 |
| 风险拒绝 | 负面/争议/关键证据不足不包装成营销机会，正常线索也不机械全部拒绝 | 创意正文借势，末尾免责掩盖风险 |

`pass`/`fail`都必须填写核查说明和支持它的来源；`unverified`单列，不能当正确；`not_applicable`用于本项没有适用对象，不能与未核实混用。没有交付不能记合格。必要事实覆盖率用预先基准；空输出、漏答、服务错误和预算停止单列，不能靠拒绝所有输出提高准确性。

导出核验包时隐藏A/B/C和工具、模型、费用标识，将同一事件匿名结果打乱；映射独立保管。开发者仍可能从文风、引用样式推断组别，这是**部分盲化**。来源语义支持性需开发者逐条查证，自动 Schema/哈希检查不叫事实金标。不用另一个模型的评分替代运营专业判断。

此外保存每次调用的 `*.input.json`、原始最终 `*.final.json` 和 `*.delivery.json`。最终文本在格式校验前保存，所以模型尝试的错误与系统实际交付可分开核查。只记录最终 `content`/文本内容块及安全用量元数据，不保存 `reasoning_content`、thinking、signature、加密推理或请求认证头。

完成匿名事实核查后再解盲。按预定规则给出三类案例：C错误减少且覆盖不下降、两者相近、C失败或更贵却无改善；类别不存在就如实写没有，不强行挑出“成功”。只有10例且有选择偏差，结果写探索性比较，不能写“显著优于”或“证明TapTap增长”。

## 确定性机制与后续消融

以下已有测试可以不花模型额度检查机制是否起作用。它们是合成反例与故障测试，不是本轮真实LLM效果结果。

| 机制 | 可复查反例 | 已有检查 |
| --- | --- | --- |
| 日期核验 | 未来日期或旧内容被重新采集，日期不得变成已确认新事件 | `test_main_agent` 的无依据日期保留核心/时间清空检查、时效相关测试 |
| 引用核验 | 编造引用编号或逐字引句，不能落库 | `test_runtime16` 的跨适配器引用检查、`test_main_agent` 的素材逐字核对 |
| 风险控制 | 子 Agent 识别负面，主 Agent 的正面措辞不能覆盖它 | `test_risk_and_comments` 的负面风险与创意禁止检查 |
| 持久执行 | 提交前后崩溃、租约过期，不能重复交付或让旧执行者写入 | `test_runtime16` 的真实多连接/进程崩溃检查 |

“去掉机制”与“普通基线”不同。真实生成的逐项消融，需要在独立数据库中从同一证据包重跑相同模型，预先指定唯一删去因素并单独批准预算；不关闭线上安全守卫。当前工具没有实现或宣称完成付费的研究子 Agent 消融、全部提示词消融或持久队列对照。先完成A/B/C，避免一次实验混入太多变量。

## 复现步骤

在项目根目录运行；下面的维护者实验命令不是网站使用者操作。`data/v3/experiments/`已被Git忽略，不提交来源原文、截图、评论、模型原始输出或账户凭证。

```powershell
$studyRoot = 'data/v3/experiments/validation-20261010-v1'
python -X utf8 scripts/benchmark_v3.py --root $studyRoot prepare --limit 240
```

程序生成 `pool.json`。核查并准备 `pilot-selection.json`（2例）和 `formal-selection.json`（10例），以下为**格式示例，不是真实事件事实**：

```json
{
  "cases": [
    {
      "case_id": "从pool.json复制编号",
      "category": "new_event",
      "selection_reason": "为何预先纳入该事件、对应哪个诊断条件",
      "reference_facts": [
        {"text": "已核查的必要事实", "url": "https://实际原始来源", "quote": "实际支持该事实的原文"}
      ]
    }
  ]
}
```

```powershell
python -X utf8 scripts/benchmark_v3.py --root $studyRoot freeze --phase pilot --selection pilot-selection.json
# 仅在用户确认充值完成及额度上限后执行一次授权：
python -X utf8 scripts/benchmark_v3.py --root $studyRoot authorize --cap-yuan 10 --pilot-yuan 2 --note '已收到用户明确授权并确认充值完成'
python -X utf8 scripts/benchmark_v3.py --root $studyRoot run --phase pilot
# 校准结束、模型/提示词/代码确定后，再冻结正式协议：
python -X utf8 scripts/benchmark_v3.py --root $studyRoot freeze --phase formal --selection formal-selection.json
python -X utf8 scripts/benchmark_v3.py --root $studyRoot run --phase formal
python -X utf8 scripts/benchmark_v3.py --root $studyRoot review --phase formal
```

核验副本填写后，以输出的review和mapping路径汇总：

```powershell
python -X utf8 scripts/benchmark_v3.py --root $studyRoot summary --phase formal --review '核验副本.json' --mapping '对应映射.json'
python -X utf8 -m unittest agent_v3.tests.test_benchmark -q
```

没有授权的`run`在联网模型调用前拒绝；已有记录不会静默重跑。崩溃遗留的预留和试次保留，不做“重新跑到成功”；如要重复必须创建独立、有说明的新批次。汇总保留所有30个预定试次，没跑的也显示，不能删掉失败组。每份原始输出、核验包和汇总均新建；没有删除旧文件。

当前已准备真实240条候选快照。17项新增离线检查验证未授权不调用、预算保留、未知用量停止、无效最终文本保留与推理隔离、模型漂移停止、实际六阶段生产路径、样本冻结、匿名核验和缺失结果；模拟的六组校准流程贯通执行、留档及汇总。**这些检查证明实验工具可用，不是项目已经胜出。**
