# 数据处理规格（可落地版）

> 输入：`02数据/reviews.csv`（TapTap 明日方舟评价，约 3000 条）  
> 目标：清洗质检 → LLM 结构化标注 → 可供日/周报聚合的标注表  
> 对照原稿：`原始数据处理提示词.md`

---

## 0. 角色 / 目标 / 非目标

| 项 | 内容 |
|----|------|
| 角色 | 数据工程师 + 标注系统设计者 |
| 目标 | 产出 `annotations_v1_4.csv`（现行）+ 预处理报告 + 标注质检报告；字段可直接算负面占比、主题结构与修辞异动 |
| 非目标 | 不预测新评分；不编造版本号；不做用户画像；第一版不训小模型 |

**成功标准（验收）：**

1. 预处理报告给出缺失/重复/异常口径，且**不对方舟评论文本乱做均值插补**  
2. 主题枚举锁定为下方 8 类，LLM 输出可被 schema 校验  
3. 金标抽样 ≥150 条后，主题一致率、情绪一致率有明确数字  
4. 全量批跑可断点续跑

## 1. 数据预处理（适配「评价表」，不是教材习题）

### 1.1 Evidence（已知）

- 主键：`review_id`（爬虫侧已去重）  
- 核心文本：`text` / `raw_text`（爬取质检时空正文约 0）  
- 显式态度：`score_raw`（1–5），**保留原值，不让 LLM 再预测分数**  
- 可空字段：`played_spent_sec`（`hidden_spent=True` 时常见为空）  
- 其他：`publish_time_cn`、`publish_platform`、`rating_tags`、`support_count`

### 1.2 缺失值：先报告，再按字段类型处理

输出缺失统计表（字段、缺失数、缺失率）。处理规则：

| 字段类型 | 策略 |
|----------|------|
| `text` 空 | **删除**该行（无法标注）；记入剔除日志 |
| `score_raw` 空 | 极少则剔除或标 `score_missing`；**禁止**用均值/众数填评分 |
| `played_spent_sec` 空 | **保留为空**（隐藏时长），分析时单独分层；禁止插补 |
| URL/头像等 | 空可接受，不填 |

> 评价数据不是回归训练集：对评分做均值插补会扭曲舆情分布，结论也无法解释。

### 1.3 「异常值」在本项目里指什么

| 检查项 | 动作 |
|--------|------|
| `score_raw` ∉ [1,5] | 标记异常，剔除或人工看 |
| `played_spent_sec` &lt; 0 | 标记异常 |
| `text` 长度极端（如 &gt;1500 或 &gt;3000） | **不删**；进入长评通道（见 §3.4） |
| 箱线图 | 可对 `score_raw`、`played_hours`、`text_len` 出图作 EDA，**默认不因箱线外点删除评论**（低分/长评恰恰是舆情信号） |
| 重复 `review_id` | 去重保留 `last_seen_at` 最新 |

### 1.4 预处理交付

```text
02数据/processed/
  reviews_clean.csv          # 清洗后主表（增 text_len、length_bucket）
  dropped_rows.csv           # 剔除明细与原因
reports/
  preprocess_qc_*.md         # 缺失、重复、分布、箱线说明
figures/                     # 可选：score / text_len 分布图
```

`length_bucket` 建议：

- `short`：`text_len ≤ 30`  
- `mid`：`30 < text_len ≤ 300`  
- `long`：`text_len > 300`  
- `very_long`：`text_len > 1500`（标注时可能截断/摘要）

## 2. LLM 结构化标注 · Schema（契约）

### 2.1 输出字段（现行 Prompt `v1.4`）

| 字段 | 类型 | 取值 | 说明 |
|------|------|------|------|
| `review_id` | 透传 | | 与主表关联 |
| `topic_primary` | 枚举单选 | 见下表 8 类 | 日报主题结构 |
| `literal_sentiment` | 枚举 | `正` / `中` / `负` | **字面**褒贬 |
| `intended_sentiment` | 枚举 | `正` / `中` / `负` | **整体真实态度**（不是「有没有槽点」） |
| `sentiment` | 枚举 | `正` / `中` / `负` | **对外主情绪 = intended** |
| `actionable` | 枚举 | `是` / `否` | 有具体可改点可为是，即使整体=正 |
| `confidence` | 数 | `0~1` | 主题+意图整体置信 |
| `rhetoric` | 枚举 | `none` / `sarcasm` / `gaoji_hei` / `fanchuan` / `template_praise` | 修辞类型 |
| `rhetoric_confidence` | 数 | `0~1` | 修辞判定置信 |
| `incongruity_cues` | 字符串 | 见下表；多选逗号拼接；无则 `none` | **裂隙线索**（两段式第①段产物） |
| `reason` | 字符串 | ≤30 字 | 有裂隙须点明 |
| `truncated` | bool | | 超长截断标记 |
| `model` / `prompt_version` | 字符串 | | 现行 `v1.4` |

**两段式方法（v1.3 起）+ v1.4 回归微调：**

1. **① 修辞通道**：按裂隙清单扫描 → `incongruity_cues` / `literal` / `rhetoric`
2. **② 整体态度通道**：修辞命中且分裂 → 跟意图；`rhetoric=none` 时夸中轻槽/亲昵玩笑仍可正
3. **v1.4**：`star_text_conflict` 单独≠负；狗头炫耀好运→正；高星单点难度/机制建议→正或中；高星辱骂仍负

| incongruity_cues 代码 | 含义 |
|----------------------|------|
| `praise_shell_neg_fact` | 褒义外壳 + 负面事实 |
| `template_parallel` | 机械排比好评 |
| `paren_leak` | 括号/限定泄真 |
| `community_irony` | 圈梗 + 反讽收束 |
| `overstatement` | 夸张到违和 |
| `star_text_conflict` | 星级与文本强冲突（线索，非自动负） |
| `fake_recommend` | 推荐句式假动作 |
| `none` | 无裂隙 |

> 产物：`annotations_v1_4.csv`（现行）。对照见 `reports/sentiment_calib_v1_4_*.md`。

**禁止输出：** 新评分、臆造的版本名/活动名、枚举外主题/修辞/裂隙代码。

### 2.2 主题枚举（第一版锁定 8 类）

原稿把「综合吹/踩」和过细运营类拆散了；吹踩是情绪不是主题。合并为：

| 代码 | 标签 | 边界说明 |
|------|------|----------|
| `gacha` | 抽卡/商业化 | 池子、保底、氪金、月卡通行证、逼氪 |
| `balance` | 数值/平衡/养成 | 强度、练度、精二、模组、环境 |
| `gameplay` | 关卡/玩法难度 | 肉鸽、危机合约、某关卡机制、操作体验 |
| `story` | 剧情/世界观 | 主线、活动剧情、角色塑造 |
| `event` | 活动/版本内容 | 新活动内容量、玩法更新、联动（非纯抽卡吐槽） |
| `client` | 性能/客户端 | 卡顿、闪退、包体、UI、设备适配 |
| `ops` | 运营/客服/规则 | 公告、补偿、客服、活动规则说明不清 |
| `other` | 综合/其他 | 纯「好玩/垃圾」无明确对象，或多主题无法判主 |

**多主题规则：** 只选 **主诉求/主抱怨** 一类；其余可在 `reason` 点一句。  
例：「剧情好但池子毒」→ `gacha` + `sentiment=负`（主抱怨在商业化），`reason` 可写「主线满意但抽卡不满」。

### 2.3 `actionable` 口径

- **是**：出现可被产品/运营响应的具体点（掉率/保底、某关 bug、规则描述、闪退复现条件等）  
- **否**：纯情绪、空泛好坏、无对象夸赞  

### 2.4 与 `score_raw` 的关系

- 星级 **仅作参考输入**，允许与 `sentiment` 冲突  
- 质检时单独统计 **冲突率**（如 5 分但 sentiment=负）——这是洞见，不是标注失败

## 3. 标注 Prompt（可直接用于批跑）

### 3.1 System

```text
你是《明日方舟》TapTap 评价标注员。
只输出一个 JSON 对象，不要 Markdown，不要解释。
字段：topic_primary, sentiment, actionable, confidence, reason
topic_primary 必须是以下之一：gacha, balance, gameplay, story, event, client, ops, other
sentiment 必须是：正, 中, 负
actionable 必须是：是, 否
confidence 为 0 到 1 的小数；不确定时用 other 或降低 confidence
reason ≤30 个汉字，简述依据
禁止编造原文未出现的版本名、活动名、数值
若文本几乎无信息，topic_primary=other，并给出相应 sentiment
多主题时只选主诉求/主抱怨一类
```

### 3.2 User 模板

```text
score_raw: {score_raw}
text:
{text}
```

### 3.3 Few-shot（规范写法）

| 输入摘要 | 期望输出要点 |
|----------|----------------|
| text=`好玩`，score=5 | `other` / `正` / `否` / 高置信 |
| text=`抽卡歪了`，score=5 | `gacha` / `负` / `是`（若提到歪/保底）/ 中高置信 —— **星级与情绪可冲突** |
| text=`剧情好但是池子狠毒`，score=2 | `gacha` / `负` / `是` / reason 点出主抱怨在池子 |
| text=`打个树海反反复复，稍微失误全部从来`，score=2 | `gameplay` / `负` / `是`（机制挫败） |
| text=`设计关卡…第十章B…炸弹锁定都有问题`，score=2 | `gameplay` / `负` / `是` |
| text=`一百抽只出一个六星？…保底机制…拜拜`，score=1 | `gacha` / `负` / `是` |

批跑脚本里应用 JSON 示例完整写出 4～6 条，而不是口语 `==`。

### 3.4 长评策略

1. 先对原文直接标注（`truncated=false`）  
2. 若模型失败/明显跑飞：截断至前 1500 字或先摘要再标（`truncated=true`）  
3. 对 `very_long` 抽样人工复核，不默认删除  

### 3.5 短评分群

- 报表可分 `short/mid/long` 看主题分布  
- 短评 `other` 比例高是预期现象，质检时 **mid+long** 子集上的主题一致率更重要

## 4. 流水线步骤

```text
① 预处理 → reviews_clean.csv
② 分层抽金标 150～200 条（按 score 1/3/5 + 长度分层）人工标注
③ 用金标调 prompt / 温度（建议 temperature=0）
④ 小批量 100～200 条试跑，算一致率与混淆矩阵
⑤ 全量批跑 → annotations.csv（断点、重试、原始响应落盘）
⑥ 再抽 100 条质检；坏例回流 few-shot
⑦ （后续）按周聚合负面占比、主题贡献 → 日/周报
```

### 4.1 输出契约

```text
02数据/processed/reviews_clean.csv
03标注结果/annotations.csv
03标注结果/raw_llm/{review_id}.json
03标注结果/checkpoint.json
02数据/reports/preprocess_qc_*.md
03标注结果/reports/annotate_*.md
```

`annotations.csv` 至少含：`review_id, topic_primary, sentiment, actionable, confidence, reason, truncated, prompt_version, model, annotated_at`

## 5. 质检口径（写进 annotate_qc）

- 主题一致率（人工 vs 模型）；混淆矩阵 Top 易混对  
- 情绪一致率  
- `actionable` 一致率  
- 星级-情绪冲突率  
- 枚举非法率（应为 0，靠 schema）  
- 按 `length_bucket` 分层一致率  

建议门槛（第一版可调）：情绪 ≥0.85；主题（mid+long）≥0.75；非法枚举 =0。

## 6. 原稿问题对照（便于你练 PE）

| 原稿 | 问题 | 本规格改法 |
|------|------|------------|
| 缺失值套「均值/插值」 | 不适合评分/文本舆情 | 分字段策略；禁止填评分 |
| 箱线异常就删 | 低分长评是信号 | 箱线只做 EDA |
| 主题 12+ 且含吹/踩 | 吹踩是情绪；类过多难质检 | 锁 8 类 |
| `actionable` 未写清 | 模型乱标 | 明确是/否口径 |
| few-shot 口语 `==` | 不可直接喂 API | 改为完整 JSON 样例 |
| 无输出/验收契约 | 无法判断做完没有 | §0 §4 §5 |
