# 讽刺 / 反串 / 高级黑：资料检索与标注口径（方舟舆情）

> 整理时间：2026-07-21  
> 用途：补强 LLM 结构化标注对「字面褒义、意图贬义」类评论的识别  
> 触发：小样本中模型未识别讽刺/反串/高级黑（用户提供方舟社区例句）

---

## 1. 问题是什么

当前 schema 只有 `sentiment ∈ {正,中,负}`，模型倾向跟**字面褒义词**走，容易把下面这类判成「正 / other」：

**例 A（高级黑 / 阴阳怪气）**

> 好玩的游戏，游戏体验感极佳（可能只是因为议长大人带给我的体验），没出之前我是退过几次坑的，抄攻略不会抄，不抄打不过，但有了议长大人就不一样了，六炮打不死那就再部署再打六炮😋  
> 我们方舟最需要脑

字面：好玩、体验极佳、需要脑。  
意图：嘲关卡设计/容错/依赖攻略或特定干员（议长），emoji 与「最需要脑」常为反讽收束。

**例 B（排比式反串 / 假推荐）**

> 音乐是顶级的，画面是优质的，玩法是有意思的，推荐是下载的

字面：全面好评并推荐下载。  
意图：机械排比 + 「推荐是下载的」句式别扭，社区常见**敷衍五星/反串好评**或阴阳模板，真实态度往往中性偏负或「不可当真的正」。

这类样本若只标 `sentiment=正`，日报告警会**漏掉阴损吐槽**，与「异动下钻」目标冲突。

## 2. 概念口径（标注前先对齐）

| 社区说法 | 近似学术/产业说法 | 操作定义（本项目） |
|----------|-------------------|-------------------|
| 讽刺 / 反话 | sarcasm / irony | 字面义与真实态度相反或强烈错位 |
| 阴阳怪气 | 隐晦负面 + 礼貌/褒义外壳 | 褒义词包装不满，常带转折、括号吐槽 |
| 高级黑 | satire / overstatement praise | 「夸着夸着在骂」：表面全面肯定，细节全是槽点 |
| 反串 | astroturf / troll / 假人设评价 | 假装某立场发帖（假好评、假差评、引战）；**不等于**所有讽刺 |
| 暗号评价 | dog-whistle / coded review | 圈内梗才能听懂，脱离语境易判错 |

> 注意：TapTap 另有「诱导好评」平台规则（有奖换五星），与「玩家自发阴阳」不同，勿混为一谈。  
> 文档：https://developer.taptap.cn/docs/store/operation/advanced-guide/review/astroturfers/

## 4. 可操作的识别线索（写进 Prompt / 质检表）

结合资料与方舟例句，优先查这些 **字面–意图裂隙**：

1. **褒义外壳 + 负面事实**  
   「体验极佳」+「退坑 / 打不过 / 六炮打不死」  
2. **机械排比好评**  
   「音乐是…画面是…玩法是…推荐是…」句式整齐、信息密度低  
3. **括号泄真 / 限定夸赞**  
   「（可能只是因为议长大人…）」把表扬缩成「靠某一个东西才玩得下去」  
4. **圈内梗 + 反讽收束**  
   「我们方舟最需要脑」、😋、xswl、绝了、好家伙  
5. **夸张到违和**  
   「顶级 / 极佳 / 永远的神」叠满，但后文全是槽  
6. **星级–文本冲突**（你们已有探查）  
   5 星长文阴阳；1 星反串吹（相对少）  
7. **推荐句式假动作**  
   「推荐是下载的」——像完成任务式好评，不像真心安利  

**不要**仅靠关键词「好玩」「顶级」判正。

## 5. 对你们标注 Schema 的建议（下一版）

在现有 `topic / sentiment / actionable / confidence / reason` 上增加一层（MVP）：

| 字段 | 取值 | 说明 |
|------|------|------|
| `literal_sentiment` | 正/中/负 | 字面态度 |
| `intended_sentiment` | 正/中/负 | 真实态度（日报主用这个，或与原 `sentiment` 对齐为意图） |
| `rhetoric` | `none` / `sarcasm` / `gaoji_hei` / `fanchuan` / `template_praise` | 单选主修辞；不确定 `none` + 低置信 |
| `rhetoric_confidence` | 0–1 | 修辞判定把握 |

口径草案：

- `sarcasm`：明确反话/阴阳  
- `gaoji_hei`：整段像夸，细节全是骂（高级黑）  
- `fanchuan`：强烈像假人设/引战/立场扮演（慎标，证据不足用 sarcasm）  
- `template_praise`：排比敷衍好评（可与高星一起进「可疑好评」队列，未必等于负）

日报指标建议：

- 主情绪用 **`intended_sentiment`**  
- 另报：`rhetoric != none` 占比、以及「字面正且意图负」条数  

例 A 期望大致：`literal=正`，`intended=负`，`rhetoric=gaoji_hei` 或 `sarcasm`，`topic=gameplay`。  
例 B 期望大致：`literal=正`，`intended=中或负`，`rhetoric=template_praise` 或 `sarcasm`，`topic=other`，`actionable=否`。

## 6. Prompt 补丁方向（实现时）

在 System 中显式加：

1. 必须先判断「字面 vs 意图」是否分裂  
2. 分裂则 `intended_sentiment` 跟意图，`rhetoric` 非 none  
3. Few-shot 必须包含用户这两条（及 1～2 条真好评对照，防止过度敏感）  
4. CoT 可要求模型在 `reason` 里写清裂隙点（≤30 字），例如「褒义外壳+打不过/六炮」  

学术侧（Sarcasm-R1 / EICR）也支持：让模型做 **情感不协调推理**，比直接问「正负」更稳。

## 7. 边界（报告怎么写）

- 讽刺识别是业界公认难点；小样本无人工金标时，只称「规则+LLM 探查」，不写未经核验的高准确率。  
- 反串（假好评水军）与玩家阴阳是不同问题；后者更适合本项目第一版。  
- 圈内梗（议长等）会过时，质检坏例要回流 few-shot。
