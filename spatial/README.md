## 第八版：任务入口与操作指导

主导航按“找机会 / 做方案 / 我的项目 / 工作台”组织。游戏与品类、素材与策略、记录时间线仍可从资料工具、页脚或全站搜索进入，原有深链接继续有效。“我的项目”专门找回已有工作，显示当前步骤、成果和行动，可筛选、归档、备份与导入；新建任务集中在“做方案”。

采用方向后先进入来源页。保存的最新成果版本可带入工作台，交接资料继续冻结保留。3D 项目资料空间可按需展开，来源关系空间、创意画布和已有员工功能继续保留。工作台各页提供可展开的三步说明。指南支持键盘、焦点返回、减少动画；手机步骤横向滚动，页面本身不横向溢出。创建保存失败会保留草稿，重试沿用同一项目，换连接或关闭指南不会将用户带到错误的项目。

## 第七版：员工工作台与研究交接

`#/workbench` 现在提供面向 TapTap 内容、社区和增长运营的行动空间。今日机会采用当前情报快照，可按明确的游戏、品类与热点类型设置关注范围，手动标记关注、暂缓或忽略。保存一次基线后，可以比较两次记录的热点强度；不补造实时变化或全网覆盖。已有研究区、3D 证据空间与创意画布继续保留。

研究方向、当前简报或选定的成果版本可带入员工工作台。加入时冻结方案、引用来源、已保存创作和验证计划，后续修改研究不会覆盖交接资料。同一方向默认打开原行动，也可显式另建独立行动。工作台可填写负责人、优先级、截止日、游戏运营阶段，使用任务清单与处理历史推进，并按列表、阶段或排期日历查看。阶段建议追加任务，保留已有任务和完成状态；行动归档可以恢复，研究归档不会隐藏其行动。

每个行动独立填写验证计划、手动观察、复盘结论与后续决策。日报和周报按上海时区选择有建立、编辑或进展记录的行动，展示当前记录状态，不还原历史时点状态。交付包导出包含行动记录与加入时的研究资料。完整 JSON 工作台备份可独立导入，保留来源情境与快照，分配新行动标识。研究分支保留资料，员工行动继续留在原研究。保存失败和本地存储回退会显示在界面中。

当前仍是前端本地产品体验：演示热点为合成数据、建议为规则编排，未连接真实模型、采集任务、员工身份、团队同步、审批或发布系统。负责人是手动文字记录。按演示、API 地址与账户连接隔离保存。经典工作台保留在 `#/workbench?page=legacy`。继续本地预览，未推送 GitHub 或启用 Pages。

## 第四版：连续的增长研究流程

用户从一个问题开始，进入独立研究会话，依次完成「发现线索 → 形成判断 → 编排方案 → 整理成果」。在同一份研究里可添加不同游戏的热点、选用来源素材、写下有明确引用的观察或推测、编辑 TapTap 增长方向并下载简报。研究分支独立保存，成果版本冻结当时的正文、判断和来源快照。

- `#/home` / `#/ai`：研究入口，支持游戏名、话题关键词、明确的品类标签和通用热点问题；限定游戏、平台、首次记录范围和升温阶段。最近的研究会恢复原会话。
- `#/research`：研究列表、搜索、可恢复的归档、JSON 备份与独立导入；旧研究可导入为新会话，旧笔记继续保留。
- `#/research?session=…`：连续研究视图。左侧保留热点目录，中间整理证据与增长计划，右侧检查来源。手机采用横向目录和可用键盘关闭的证据弹层。支持真实读取进度、暂停、恢复和失败重试。
- `#/signals`：热点档案索引、游戏/平台/阶段筛选、关注和最多三个热点比较。
- `#/games`：游戏档案、明确标签下的品类热点与游戏比较。示例品类有说明，真实模式不自行猜测类型。
- `#/timeline`：首次记录时间线、日期与平台筛选。演示讨论量图为合成数据，真实模式不补造历史。
- `#/library`：来源素材、原文链接、复制、收藏、选择下载以及已有增长策略。
- `#/notes`：第三版研究笔记；`#/workbench`：员工工作台；`#/workbench?page=legacy`：经典工作台。

证据引用采用稳定标识，素材重新排序不会改变引用。重新读取保留旧快照，原文内容变化后仍可追溯已引用的片段。合成演示、API 快照和来源未标注的导入记录保留各自的来源标记，跨连接导入不会改变来源类型。证据详情区分原文发布时间和前端读取时间，并保留上游提供的素材使用条件；信息缺失时显示未提供。判断只引用用户明确选择的来源，方案只使用明确选入的判断，观察和推测保持区分。

## 3D 与产品动画

视觉沿用印刷档案概念：本地可变中文字体、纸面底色、荧光绿索引、蓝色编辑信息和橙色提示。首页的 Three.js 档案具有厚度、弯曲纸张、金属夹、阴影和可开合封面；拖动旋转、双击归位、点击纸张打开情报。

研究里的纸张对应当前热点、选用的证据和增长简报，阶段切换会改变纸面的内容与点击行为。场景不读取 API，只消费已经保存的业务数据；动画按需渲染，研究场景离开可视区后停止渲染。手机默认轻量画质，可减少动画；WebGL 不可用时保留同样可点击的档案入口。

字体基于 Noto Sans SC，可变 WOFF2 保存在 `public/fonts`，授权见同目录 `OFL.txt`。设计方法参考 [frontend-design](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)，研究了 [Lusion](https://lusion.co/) 与 [14islands](https://www.14islands.com/) 的呈现方法；本项目实现自己的几何、印刷纹理、版式和交互。

```powershell

$env:VITE_DEMO_MODE = "false"
```

## 网站与后端的边界

GitHub Pages 托管 HTML、JavaScript、CSS 和静态图片，不运行 Python/FastAPI、常驻采集器或数据库服务。因此，Pages 能直接提供 3D 演示网站；实时采集、登录和生成创意需要独立部署项目后端。GitHub Actions 负责构建与发布，不承担常驻 API 服务。

独立后端必须提供 HTTPS。在后端部署环境设置 `WEBAPP_ALLOWED_ORIGINS=https://hccccc01333.github.io` 后，FastAPI 会允许该网站来源的 CORS 请求；多个来源用英文逗号分隔，如设置自定义域名，应加入对应域名。来源不包含仓库路径，且必须精确匹配协议、域名和端口。默认不开放跨域；本地同源 Vite proxy 不需要 CORS。

所有 `VITE_*` 配置都会进入公开前端；其中只放模式、路径和公开后端地址，采集 Cookie、API 密钥和后台密码放在后端环境中。对外真实部署应使用正式认证；仓库的 `demo` 账号用于本地演示。
